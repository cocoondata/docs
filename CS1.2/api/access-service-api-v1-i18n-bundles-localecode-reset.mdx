## URL structure <a id="access-service-api-v1-i18n-bundles-localecode-reset-url-structure" />

```text
https://access-service.xy-company.com/api/v1/i18n/bundles/{localeCode}/reset
```

where `{localeCode}` is a supported locale code.

## Supported methods and overview <a id="access-service-api-v1-i18n-bundles-localecode-reset-supported-methods-and-overview" />

- `PUT` - resets a locale from a custom internationalisation (i18n) bundle (specified by `{localCode}` and which had been uploaded to the Cocoon Data Platform's Access Service) back to its built in version.

<Note>

This method takes no parameters.

</Note>

## Detailed description <a id="access-service-api-v1-i18n-bundles-localecode-reset-detailed-description" />

This API endpoint resets a locale from a custom i18n bundle (specified by `{localCode}` and which had been uploaded to the Cocoon Data Platform's Access Service) back to its built in version.

<Note>

- This endpoint can only be called on locales *with* existing i18n bundles that are built in to the Cocoon Data Platform.
- Any Cocoon Data users utilising the locale of this custom i18n bundle (which they would have chosen through SafeShare) will automatically be reverted to use the existing i18n bundle of the same locale, when the bundle is reset.

</Note>

This API endpoint supports the following Cocoon Data user [roles](/CS1.2/admin-platform/administering-platform-administrator-users#platform-administrators-and-user-roles) (as described in the [SafeShare Administrator's Guide](/CS1.2/admin-platform)):

- [SafeShare administrator](/CS1.2/admin-platform/administering-platform-administrator-users#platform-administrator-role)

The Cocoon Data Platform's resources available to a Cocoon Data user meeting the criteria above is determined by the access token submitted in the [header](/CS1.2/api/access-service-api-v1-i18n-bundles-localecode-reset#access-service-api-v1-i18n-bundles-localecode-reset-required-headers) of requests to this endpoint.
