## URL structure <a id="content-service-api-v1-versions-versionid-view-url-structure" />

```text
https://content-service.xy-company.com/api/v1/versions/{versionId}/view
```

where `{versionId}` is the ID of a file object's/Secure Object's version.

## Supported methods and overview <a id="content-service-api-v1-versions-versionid-view-supported-methods-and-overview" />

- `GET` - downloads the encrypted *read-only view* data associated with a specific file object/[Secure Object](/CS1.2/api/working-with-files-and-folders-fundamentals#secure-object) version (specified by `versionId`) from storage via the Cocoon Data Platform's Content Service.

## Detailed description <a id="content-service-api-v1-versions-versionid-view-detailed-description" />

This API endpoint downloads the encrypted *read-only view* data associated with a specific file object version (specified by `versionId`) from storage via the Cocoon Data Platform's Content Service.

<Note>

The key required to decrypt this *read-only view* can be obtained by calling the [&lt;access-service&gt;/api/v1/versions/\{versionId\}/viewKey](/CS1.2/api/access-service-api-v1-versions-versionid-viewkey) API endpoint.

</Note>

## Supported roles and conditions <a id="content-service-api-v1-versions-versionid-view-supported-roles-and-conditions" />

This API endpoint supports requests utilizing Cocoon Data user accounts with the following [roles](/CS1.2/admin-org/administering-users-within-an-organisation#an-organisation-users-roles) (as described in the [Organisation Administrator's Guide](/CS1.2/admin-org)) and conditions:

- [Originator](/CS1.2/admin-org/administering-users-within-an-organisation#originator-role) - when this user owns the file object associated with the version whose ID is specified by `{versionId}` in the request's URL.
- **Originator**, [Collaborator](/CS1.2/admin-org/administering-users-within-an-organisation#collaborator-role) and [Ad hoc](/CS1.2/admin-org/administering-users-within-an-organisation#adhoc-role) - when this user is a collaborator with the **Rename** [permission](/CS1.2/api/access-service-api-v1-permissions-sets) on the file object associated with the version whose ID is specified by `{versionId}` in the URL. (The **Rename** permission restricts access to collaborators who have been applied either the **Modify** or **Manage** *permission set* on this file object.)

The Cocoon Data Platform's resources available to a Cocoon Data user meeting the criteria above is determined by the access token submitted in the [header](/CS1.2/api/content-service-api-v1-versions-versionid-view#content-service-api-v1-versions-versionid-view-required-headers) of requests to this endpoint.

## Required parameters <a id="content-service-api-v1-versions-versionid-view-required-parameters" />

The following parameter must be sent in the **URL** of the request:

- **format** - Specify the value `encrypted` to download the file version's encrypted *read-only view* data 'as is'; decryption must be conducted locally by your client application. <br />
  **Example:**

  ```text
  https://content-service.xy-company.com/api/v1/versions/987654321098765432/view?format=encrypted
  ```

<Note>

This required parameter will be removed in a future Cocoon Data Platform version.

</Note>

## Optional parameters <a id="content-service-api-v1-versions-versionid-view-optional-parameters" />

The following optional parameter can be sent in the **URL** of the request:

- **encoding** - Specify the value `base64` to download the file version's data as [Base64](https://tools.ietf.org/html/rfc4648)-encoded data. Otherwise, omit this parameter to download the file version's data as raw/binary data. In both cases, the `Content-Type` in the response is `application/octet-stream`.

  **Example:**

  ```text
  https://content-service.xy-company.com/api/v1/versions/987654321098765432/view?format=encrypted&encoding=base64
  ```

## Returns <a id="content-service-api-v1-versions-versionid-view-returns" />

If the request succeeded, then an HTTP response status `200 OK` is returned.
