## URL structure <a id="access-service-api-v1-organisations-orggroupid-users-userid-itemcount-url-structure" />

```text
https://access-service.xy-company.com/api/v1/organisations/{orgGroupId}/users/{userId}/itemCount
```

where `{orgGroupId}` is the ID of an organisation and `{userId}` is the ID of a Cocoon Data user account.

## Supported methods and overview <a id="access-service-api-v1-organisations-orggroupid-users-userid-itemcount-supported-methods-and-overview" />

- `GET` - retrieves the total number of file objects/[Secure Object](/CS1.2/api/working-with-files-and-folders-fundamentals#secure-object)s currently owned by a [Cocoon Data user](/CS1.2/api/authentication-and-authorisation) (specified by `userId`) within an organisation (specified by `orgGroupId`).

<Note>

This method takes no parameters.

</Note>

## Detailed description <a id="access-service-api-v1-organisations-orggroupid-users-userid-itemcount-detailed-description" />

This API endpoint retrieves the total number of file objects/Secure Objects currently owned by a Cocoon Data user (specified by `userId`) within an organisation (specified by `orgGroupId`).

A Cocoon Data user's ID can be obtained by calling the `GET` method of the [&lt;access-service&gt;/api/v1/organisations/\{orgGroupId\}/users](/CS1.2/api/access-service-api-v1-organisations-orggroupid-users) API endpoint, which retrieves a list of information associated with existing users in an organisation (specified by `orgGroupId`), which can be filtered through a variety of 'search' criteria.

This endpoint is useful for determining the number of file objects that a Cocoon Data user owns, before [transferring the ownership of these items](/CS1.2/api/access-service-api-v1-organisations-orgid-items-transfer) over to another user.

<Note>

Although this endpoint indicates [items](/CS1.2/api/working-with-files-and-folders-fundamentals#item) in its URL, calling it only returns the total number of file objects (i.e. folders/[collections](/CS1.2/api/working-with-files-and-folders-fundamentals#collection) are not counted). However, when actually transferring the ownership of items from one Cocoon Data user to another, all of the user's items (i.e. all their file objects and folders) are transferred.

</Note>

## Supported roles and conditions <a id="access-service-api-v1-organisations-orggroupid-users-userid-itemcount-supported-roles-and-conditions" />

This API endpoint supports requests utilising Cocoon Data user accounts with the following [roles](/CS1.2/admin-org/administering-users-within-an-organisation#an-organisation-users-roles) (as described in the [Organisation Administrator's Guide](/CS1.2/admin-org)) and conditions:

- [Organisation administrator](/CS1.2/admin-org/administering-users-within-an-organisation#organisation-administrator-role) - when this user is a member of the organisation specified by `{orgGroupId}` in the request's URL.

The Cocoon Data Platform's resources available to a Cocoon Data user meeting the criteria above is determined by the access token submitted in the [header](/CS1.2/api/access-service-api-v1-organisations-orggroupid-users-userid-itemcount#access-service-api-v1-organisations-orggroupid-users-userid-itemcount-required-headers) of requests to this endpoint.
