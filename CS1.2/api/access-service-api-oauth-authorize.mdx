## URL structure <a id="access-service-api-oauth-authorize-url-structure" />

```text
https://access-service.xy-company.com/api/oauth/authorize
```

## Supported methods and overview <a id="access-service-api-oauth-authorize-supported-methods-and-overview" />

- `GET` - [initiates the process for obtaining an access token](/CS1.2/api/authentication-and-authorisation#initiating-authentication-and-authorisation) (and optional refresh token) using either the *authorization code* or *implicit* OAuth 2.0 grant types.

## Detailed description <a id="access-service-api-oauth-authorize-detailed-description" />

This API endpoint initiates the process for obtaining an [access token](/CS1.2/admin-platform/configuring-client-applications#grant-types) using either [authorization code](/CS1.2/api/authentication-and-authorisation#using-the-authorization-code-grant-type) or [implicit](/CS1.2/api/authentication-and-authorisation#using-the-implicit-grant-type) OAuth 2.0 grant types.

When using the implicit grant type, the access token itself is returned in the [response](/CS1.2/api/access-service-api-oauth-authorize#access-service-api-authorize-token-returns) to this API endpoint. (All other grant types return their access tokens in calls to the [&lt;access-service&gt;/api/oauth/token](/CS1.2/api/access-service-api-oauth-token) endpoint.)

If the [client application has been configured](/CS1.2/admin-platform/configuring-client-applications) on the Cocoon Data Platform to issue refresh tokens, then a refresh token will accompany the access token. However, regardless of this configuration, refresh tokens are never issued when using the implicit grant type.

## Required parameters <a id="access-service-api-oauth-authorize-required-parameters" />

The following required parameters must be sent in the **URL** of the request:

- **response_type** - For the *authorization code* grant type, specify the string value `code` or for the *implicit* grant type, specify `token`.
- **client_id** - The client ID of your application's client credentials, which would have been generated when your application was [registered](/CS1.2/api/authentication-and-authorisation#registering-your-application-on-the-platform) on the Cocoon Data Platform.
- **redirect_uri** - Your application's URL/URI, which for the:

  - *authorization code* grant type, will handle the initial response from the Cocoon Data Platform that contains the actual authorization code. This initial response is sent after the user has successfully authenticated.
  - *implicit* grant type, will handle the response from the Cocoon Data Platform that contains the access token itself. This response is sent after the user has successfully authenticated.

  **Example (request - using the authorization code grant type):**

  ```text
  https://access-service.xy-company.com/api/oauth/authorize?response_type=code&client_id=exampleClientApplication&redirect_uri=https%3A%2F%2Fmy-application-url%2Fauthcallback
  ```

This request results in the Cocoon Data Platform presenting the user with the Cocoon Data Sign-in page.

If the client application requesting this API endpoint was developed by a third party (i.e. a non-Cocoon Data client application), then an additional page is presented requesting the user to approve the client application access to the user's resources on the Cocoon Data Platform. This step is known as the *application approval* step and only needs to be performed once (unless this approval is subsequently [revoked by the user](/CS1.2/api/access-service-api-v1-users-me-applications-approvals-approvalid)).

## Returns <a id="access-service-api-authorize-token-returns" />

Once the Cocoon Data user has successfully authenticated (and if required, has accepted the *application approval* step), the Cocoon Data Platform responds by redirecting to your application's URL/URI (i.e. the `redirect_uri` value above), whose following URL parameters depend on the grant type used:

- **code** ( *Authorization code grant type only* ) - The authorization code value.
- **access_token** ( *Implicit grant type only* ) - The access token itself, as a [JSON Web Token (JWT)](https://jwt.io/introduction/) value. The resources (i.e. API endpoints) of the Cocoon Data Platform that this access token grants permission to are based on the Cocoon Data user whose credentials were used for authentication, this user's [roles](/CS1.2/admin-org/administering-users-within-an-organisation#an-organisation-users-roles) (explained in more detail in the [Organisation Administrator's Guide](/CS1.2/admin-org/index)) and if applicable to the API endpoint, the user's:

  - membership of organisations and
  - ownership or collaborator status on files or folders.
- **token_type** ( *Implicit grant type only* ) - The brief description for the type of token (above) - i.e. usually `bearer`.
- **scope** ( *Implicit grant type only* ) - .
- **jti** ( *Implicit grant type only* ) - The UUID value for the returned JWT access token. This value is a unique ID for the returned JWT, which is also known as a JWT ID. <br />
  **Example (response/redirect - using the authorization code grant type):**

  ```text
  https://my-application-url/authcallback?code=lEQmsFkB02NGPaB3YtaDnA
  ```
