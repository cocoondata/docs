## URL structure <a id="access-service-api-v1-clientapps-url-structure" />

```text
https://access-service.xy-company.com/api/v1/clientapps
```

## Supported methods and overview <a id="access-service-api-v1-clientapps-supported-methods-and-overview" />

- `POST` - registers a new [client application](/3.5/admin-platform/configuring-client-applications) with the Covata Platform.
- `GET` - retrieves a list of information for all client applications currently registered on the Covata Platform.

## Detailed description <a id="access-service-api-v1-clientapps-detailed-description" />

This API endpoint serves a number of purposes:

- Registers a new client application with the Covata Platform for the purposes of configuring that client application's identity (as well as the applcation's Covata user authentication and authorisation) with the Covata Platform via the [OAuth 2.0 Authorisation Framework](http://tools.ietf.org/html/rfc6749).
- Retrieves a list of information about the OAuth 2.0 configuration of all client applications currently registered on the Covata Platform.

## Supported roles <a id="access-service-api-v1-clientapps-supported-roles" />

This API endpoint supports the following Covata user [roles](/3.5/admin-platform/administering-platform-administrator-users#platform-administrators-and-user-roles) (as described in the [SafeShare Administrator's Guide](/3.5/admin-platform)):

- [SafeShare administrator](/3.5/admin-platform/administering-platform-administrator-users#platform-administrator-role)

The Covata Platform's resources available to a Covata user meeting the criteria above is determined by the access token submitted in the [header](/3.5/api/access-service-api-v1-clientapps#access-service-api-v1-clientapps-required-headers) of requests to this endpoint.

## Required POST-request parameters <a id="access-service-api-v1-clientapps-required-post-request-parameters" />

The following required parameters must be sent in the **body** of the POST request, as individual members of a **JSON object**:

- **appName** - The name for the new client application which will appear to Covata users (when they attempt to authenticate to the Covata Platform from this client application).
- **clientId** - The [client ID](/3.5/admin-platform/configuring-client-applications#client-id) for this client application.
- **clientSecret** - The [client secret](/3.5/admin-platform/configuring-client-applications#client-secret) for this client application.
- **accessTokenValiditySeconds** - The number of seconds that an access token issued by the Covata Platform to this client application is valid for.
- **authorisedGrantTypes** - An array of elements, each of which is an enumeration (enum) value representing a [grant type](/3.5/admin-platform/configuring-client-applications#grant-types) (also known as [*authorisation grant*](http://tools.ietf.org/html/rfc6749#section-1.3)) that the Covata Platform will permit this client application to use to issue the application with an [*access token*](http://tools.ietf.org/html/rfc6749#section-1.4). Valid values include:

  - `authorisation_code` - An OAuth 2.0 grant type best suited for client applications that are server-side web applications, native desktop/laptop or mobile device applications. See [Authorisation Code](/3.5/admin-platform/configuring-client-applications#authorisation-code-characteristics) in the [Grant type details](/3.5/admin-platform/configuring-client-applications#grant-type-details) section/table of the SafeShare Administrator's Guide for more information.
  - `implicit` - An OAuth 2.0 grant type best suited for client applications that are user agent-based applications, such as one that runs client-side in a web browser. However, this grant type does not support the use of refresh tokens. See [Implicit](/3.5/admin-platform/configuring-client-applications#implicit-characteristics) in the Grant type details section/table of the SafeShare Administrator's Guide for more information.
  - `password` - An OAuth 2.0 grant type best suited for client applications that are native desktop/laptop or mobile device applications, or administrator/system-run services, such as a scheduled job. See [Password](/3.5/admin-platform/configuring-client-applications#password-characteristics) in the Grant type details section/table of the SafeShare Administrator's Guide for more information.
  - `refresh_token` - An option (supporting the OAuth 2.0 grant types above) that determines if the Covata Platform can issue refresh tokens to this client application, which the application can then use to request for new access tokens.
  - `mfa` - An option (supporting the OAuth 2.0 grant types above) that determines if the Covata Platform will permit this client application to support Covata users authenticating with 2FA enabled. <br />
    **Note:** This feature is not available for selection in [SafeShare Administration](/3.5/admin-platform) (i.e. through the ['Client Applications' configuration page](/3.5/admin-platform/configuring-client-applications)) and does not appear anywhere throughout the user interface of SafeShare Administration. However, when configuring a client application through SafeShare Administration, this option is always automatically chosen.
  - `device` - An option (supporting the OAuth 2.0 grant types above) that determines if the client application (running on a specific device - typically on a mobile device platform such as iOS or Android) can authenticate a specific Covata user with a passcode.
- **refreshTokenValiditySeconds** ( only required when **authorisedGrantTypes** includes `refresh_token` ) - The number of seconds that a refresh token issued by the Covata Platform to a client application is valid for. This value must be greater than the **accessTokenValiditySeconds** value above.
- **registeredRedirectUris** ( only required when **authorisedGrantTypes** includes `authorisation_code` and/or `password` ) - A list of one or more valid Uniform Resource Identifiers (URIs) which the Covata Platform uses to verify the value of the [*redirect URI*](http://tools.ietf.org/html/rfc6749#section-3.1.2) (also known as a *redirection endpoint*) parameter sent by the client application to the Covata Platform (during an OAuth 2.0 authentication and authorisation request to obtain an access token). <br />
  **Example (request):**

  ```json
  {
    "appName": "Example Client Application",
    "clientId": "exampleClientApplication",
    "clientSecret": "exampleClientApplicationSecret",
    "accessTokenValiditySeconds": 2419200,
    "authorisedGrantTypes": [ "authorisation_code", "implicit", "password", "refresh_token", "mfa" ],
    "refreshTokenValiditySeconds": 4838400,
    "registeredRedirectUris": "https://callback"
  }
  ```
