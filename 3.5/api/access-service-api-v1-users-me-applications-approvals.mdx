## URL structure <a id="access-service-api-v1-users-me-applications-approvals-url-structure" />

```text
https://access-service.xy-company.com/api/v1/users/me/applications/approvals
```

## Supported methods and overview <a id="access-service-api-v1-users-me-applications-approvals-supported-methods-and-overview" />

- `GET` - retrieves a list of information about third party (i.e. non-Covata) client applications which the [Covata user](/3.5/api/authentication-and-authorisation) (whose [access token is submitted in the request](/3.5/api/access-service-api-v1-users-me-applications-approvals#access-service-api-v1-users-me-applications-approvals-supported-roles) to this endpoint) has approved access to their resources on the Covata Platform.

<Note>

This method takes no parameters.

</Note>

## Detailed description <a id="access-service-api-v1-users-me-applications-approvals-detailed-description" />

This API endpoint retrieves a list of information about third party (i.e. non-Covata) client applications which the Covata user (whose access token is submitted in the request to this endpoint) has approved access to their resources on the Covata Platform.

This *application approval* process is a step that occurs after the user signs in from a third party client application which utilises the *authorisation code* or *implicit* OAuth 2.0 grant types - i.e. via the [&lt;access-service&gt;/api/oauth/authorise](/3.5/api/access-service-api-oauth-authorise) API endpoint.

Such a client application could be one that you or your organisation is developing, where this application integrates with Covata technologies using the Covata API.

<Note>

Before any client application can be granted access to a Covata user's resources, a SafeShare administrator must first have [registered the client application](/3.5/api/access-service-api-v1-clientapps) on their Covata Platform instance.

</Note>

## Supported roles <a id="access-service-api-v1-users-me-applications-approvals-supported-roles" />

This API endpoint supports requests utilising Covata user accounts with the following roles (as described in the [SafeShare Administrator's](/3.5/admin-platform/administering-platform-administrator-users#platform-administrators-and-user-roles) and [Organisation Administrator's](/3.5/admin-org/administering-users-within-an-organisation#an-organisation-users-roles) Guides):

- [Originator](/3.5/admin-org/administering-users-within-an-organisation#originator-role)
- [Collaborator](/3.5/admin-org/administering-users-within-an-organisation#collaborator-role)
- [Ad hoc](/3.5/admin-org/administering-users-within-an-organisation#adhoc-role)
- [SafeShare administrator](/3.5/admin-platform/administering-platform-administrator-users#platform-administrator-role)
- [Organisation administrator](/3.5/admin-org/administering-users-within-an-organisation#organisation-administrator-role)

The Covata Platform's resources available to one of these Covata users (above) is determined by the access token submitted in the [header](/3.5/api/access-service-api-v1-users-me-applications-approvals#access-service-api-v1-users-me-applications-approvals-required-headers) of requests to this endpoint.

## Returns <a id="access-service-api-v1-users-me-applications-approvals-returns" />

If the request succeeded, then an HTTP response status `200 OK` is returned.

For successful requests only, a JSON-formatted response containing the following members is also returned:

- **applications** - An array containing information about all third party client applications which the Covata user (whose [access token is submitted in the request](/3.5/api/access-service-api-v1-users-me-applications-approvals#access-service-api-v1-users-me-applications-approvals-supported-roles) to this endpoint) has approved access to their resources on the Covata Platform. One of this array's elements contains the member **id**, whose value is the application's approval ID, which can be utilised to [revoke the access that this application has to the user's resources](/3.5/api/access-service-api-v1-users-me-applications-approvals-approvalid).

  **Example (response):**

  ```json
  {
      "applications": []
  }
  ```
