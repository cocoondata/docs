## URL structure <a id="content-service-api-v1-objects-objectid-view-url-structure" />

```text
https://content-service.xy-company.com/api/v1/objects/{objectId}/view
```

where `{objectId}` is the ID of a file object/Secure Object.

## Supported methods and overview <a id="content-service-api-v1-objects-objectid-view-supported-methods-and-overview" />

- `GET` - downloads the encrypted *read-only view* data of a file object/[Secure Object](/3.5/api/working-with-files-and-folders-fundamentals#secure-object) (specified by `objectId`) from storage via the Covata Platform's Content Service.
- `PUT` - regenerates the *read-only view* of a file object (specified by `objectId`) based on the file object's actual data, which is also stored and managed by the Content Service.

<Note>

- The `PUT` method take no parameters.
- All methods above work with the active version of the file object (specified by `objectId`).

</Note>

## Detailed description <a id="content-service-api-v1-objects-objectid-view-detailed-description" />

This API endpoint serves a number of purposes, all of which are managed by the Covata Platform's Content Service:

- Downloads the encrypted *read-only view* data of a file object (specified by `objectId`) from storage. <br />
  **Note:** The key required to decrypt this *read-only view* can be obtained by calling the [&lt;access-service&gt;/api/v1/objects/\{objectId\}/keys/view](/3.5/api/access-service-api-v1-objects-objectid-keys-view) API endpoint.
- Regenerates the *read-only view* of a file object (specified by `objectId`) based on the file object's actual data in storage.

## Supported roles and conditions <a id="content-service-api-v1-objects-objectid-view-supported-roles-and-conditions" />

This API endpoint supports requests utilising Covata user accounts with the following [roles](/3.5/admin-org/administering-users-within-an-organisation#an-organisation-users-roles) (as described in the [Organisation Administrator's Guide](/3.5/admin-org/index)) and conditions:

- [Originator](/3.5/admin-org/administering-users-within-an-organisation#originator-role) - using the `GET` and `PUT` methods when this user owns the file object whose ID is specified by `{objectId}` in the request's URL.
- **Originator**, [Collaborator](/3.5/admin-org/administering-users-within-an-organisation#collaborator-role) and [Ad hoc](/3.5/admin-org/administering-users-within-an-organisation#adhoc-role) - using the `GET` method when this user is a collaborator with the **View** [permission](/3.5/api/access-service-api-v1-permissions-sets) on the file object whose ID is specified by `{objectId}` in the URL.

The Covata Platform's resources available to a Covata user meeting the criteria above is determined by the access token submitted in the [header](/3.5/api/content-service-api-v1-objects-objectid-view#content-service-api-v1-objects-objectid-view-required-headers) of requests to this endpoint.

## Optional parameters <a id="content-service-api-v1-objects-objectid-view-optional-parameters-on-GET" />

The following optional parameter can be sent in the **URL** of the GET request:

- **encoding** - Specify the value `base64` to download the encrypted view as [Base64](https://tools.ietf.org/html/rfc4648)-encoded data. Otherwise, omit this parameter to download the encrypted view as raw/binary data. In both cases, the `Content-Type` in the response is `application/octet-stream`.

  **Example:**

  ```text
  https://content-service.xy-company.com/api/v1/objects/987654321098765432/view?encoding=base64
  ```

## Returns <a id="content-service-api-v1-objects-objectid-view-returns-from-a-GET-or-PUT-request" />

If the request succeeded, then an HTTP response status `200 OK` is returned.
