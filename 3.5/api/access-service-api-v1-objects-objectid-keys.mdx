## URL structure <a id="access-service-api-v1-objects-objectid-keys-url-structure" />

```text
https://access-service.xy-company.com/api/v1/objects/{objectId}/keys
```

where `{objectId}` is the ID of a file object/Secure Object.

## Supported methods and overview <a id="access-service-api-v1-objects-objectid-keys-supported-methods-and-overview" />

- `GET` - retrieves the cryptographic key required to decrypt the active version of a file object/[Secure Object](/3.5/api/working-with-files-and-folders-fundamentals#secure-object) (specified by `objectId`).

<Note>

This method takes no parameters.

</Note>

## Detailed description <a id="access-service-api-v1-objects-objectid-keys-detailed-description" />

This API endpoint retrieves the cryptographic key required to decrypt the active version of a file object, using the file object's ID.

This key is generated by:

1. Calling the [&lt;access-service&gt;/api/v1/keys](/3.5/api/access-service-api-v1-keys) endpoint to obtain a cryptographic key and then
2. Associating this key with a new *Incomplete* or completed file object (by subsequently calling the [&lt;access-service&gt;/api/v1/organisations/\{orgGroupId\}/objects](/3.5/api/access-service-api-v1-organisations-orggroupid-objects) endpoint).

A file object's ID can be obtained by calling the [&lt;access-service&gt;/api/v1/organisations/\{orgId\}/items](/3.5/api/access-service-api-v1-organisations-orgid-items) API endpoint, which retrieves a list of information associated with file objects that can be filtered using various 'search' criteria.

## Supported roles and conditions <a id="access-service-api-v1-objects-objectid-keys-supported-roles-and-conditions" />

This API endpoint supports the following Covata user [roles](/3.5/admin-org/administering-users-within-an-organisation#an-organisation-users-roles) (as described in the [Organisation Administrator's Guide](/3.5/admin-org)), conditions and [permissions](/3.5/api/access-service-api-v1-permissions-sets) (where applicable):

- [Originator](/3.5/admin-org/administering-users-within-an-organisation#originator-role) - when this user owns the file object whose ID is specified by `{objectId}` in the request's URL.
- **Originator**, [Collaborator](/3.5/admin-org/administering-users-within-an-organisation#collaborator-role) and [Ad hoc](/3.5/admin-org/administering-users-within-an-organisation#adhoc-role) - when this user is a collaborator with the **Download** [permission](/3.5/api/access-service-api-v1-permissions-sets) on the file object whose ID is specified by `{objectId}` in the URL.

The Covata Platform's resources available to a Covata user meeting the criteria above is determined by the access token submitted in the [header](/3.5/api/access-service-api-v1-objects-objectid-keys#access-service-api-v1-objects-objectid-keys-required-headers) of requests to this endpoint.

## Returns <a id="access-service-api-v1-objects-objectid-keys-returns" />

If the request succeeded, then an HTTP response status `200 OK` is returned.

For successful requests only, a JSON-formatted response containing the following members is also returned:

- **keyValue** - The cryptographic key value itself.
- **cryptographicAlgorithm** - The cryptographic algorithm supported by the Covata Platform. This should be `AES`.
- **keyLength** - The bit length of the cryptographic key value returned above.
- **initializationVector** - The initialization vector required to begin local/client-side decryption using the AES algorithm (in CBC mode). <br />
  **Example:**

  ```json
  {
      "keyValue": "2VCZkPeYPhvL4VkzrEqIVGaW2AGmRM1uwuXiPRbe8NU=",
      "cryptographicAlgorithm": "AES",
      "keyLength": 256,
      "initializationVector": "fpEIYIk+dnMw7rgFA+Bz8g=="
  }
  ```
