## URL structure <a id="access-service-api-v1-users-me-applications-approvals-approvalid-url-structure" />

```text
https://access-service.xy-company.com/api/v1/users/me/applications/approvals/{approvalId}
```

where `{approvalId}` is an application's approval ID.

## Supported methods and overview <a id="access-service-api-v1-users-me-applications-approvals-approvalid-supported-methods-and-overview" />

- `DELETE` - used to revoke the access that a third party (i.e. non-Covata) client application (specified by `approvalId`) has to resources on the Covata Platform, which are accessible to a Covata user (whose [access token is submitted in the request](/3.3/api/access-service-api-v1-users-me-applications-approvals-approvalid#access-service-api-v1-users-me-applications-approvals-approvalid-supported-roles-and-conditions) to this endpoint).

<Note>

This method takes no parameters.

</Note>

## Detailed description <a id="access-service-api-v1-users-me-applications-approvals-approvalid-detailed-description" />

This API endpoint revokes the access that a third party (i.e. non-Covata) client application (specified by `approvalId`) has to resources on the Covata Platform, which are accessible to a Covata user (whose access token is submitted in the request to this endpoint).

An application's approval ID is obtained using the [&lt;access-service&gt;/api/v1/users/me/applications/approvals](/3.3/api/access-service-api-v1-users-me-applications-approvals) API endpoint, which retrieves a list of information about all client applications that this user (whose access token is submitted in the request to this endpoint) has approved access to their resources on the Covata Platform.

Such a client application could be one that you or your organization is developing, where this application integrates with Covata technologies either using the Covata API.

<Note>

Before any client application can be granted access to a Covata user's resources, a Safe Share administrator must first have [registered the client application](/3.3/api/access-service-api-v1-clientapps) on their Covata Platform instance.

</Note>

## Supported roles and conditions <a id="access-service-api-v1-users-me-applications-approvals-approvalid-supported-roles-and-conditions" />

This API endpoint supports requests utilizing Covata user accounts with the following roles (as described in the [Safe Share Administrator's](/3.3/admin-platform/administering-platform-administrator-users#platform-administrators-and-user-roles) and [Organization Administrator's](/3.3/admin-org/administering-users-within-an-organisation#an-organisation-users-roles) Guides):

- [Originator](/3.3/admin-org/administering-users-within-an-organisation#originator-role), [Collaborator](/3.3/admin-org/administering-users-within-an-organisation#collaborator-role), [Ad hoc](/3.3/admin-org/administering-users-within-an-organisation#adhoc-role), [Safe Share administrator](/3.3/admin-platform/administering-platform-administrator-users#platform-administrator-role) and [Organization administrator](/3.3/admin-org/administering-users-within-an-organisation#organisation-administrator-role) - when this user has approved the client application (specified by `{approvalId}` in the request's URL) access to their resources on the Covata Platform.

The Covata Platform's resources available to one of these Covata users (above) is determined by the access token submitted in the [header](/3.3/api/access-service-api-v1-users-me-applications-approvals-approvalid#access-service-api-v1-users-me-applications-approvals-approvalid-required-headers) of requests to this endpoint.
