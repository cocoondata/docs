Anhand der Seite **Konfiguration** können Organisations-Administratoren eine begrenzte Zahl an organisationsspezifischen Eigenschaften [ändern](/3.2/de/admin-platform/configuring-organisation-administration-properties#modifying-an-organisation-administration-property-value), um so das Verhalten und spezifische funktionelle Aspekte ihrer Organisation auf der Covata-Plattform zu optimieren.

![Seite Konfiguration/Eigenschaften](/images/e70e47bc2cf6-organisation-administration-property-configuration-page.png)
## Änderung eines Eigenschaftswerts der Safe Share-Organisationsverwaltung <a id="modifying-an-organisation-administration-property-value" />

**Änderung eines Eigenschaftswerts der Safe Share-Organisationsverwaltung:**

1. [Melden Sie sich](/3.2/de/admin-platform/accessing-organisation-administration#signing-in-to-organisation-administration) bei der Safe Share-Organisationsverwaltung an.
2. Klicken Sie auf die Option **Konfiguration** links auf der [Oberfläche Safe Share-Organisationsverwaltung](/3.2/de/admin-platform/accessing-organisation-administration#the-organisation-administration-interface), um die Seite **Konfiguration** aufzurufen.
3. Klicken Sie auf den Link **Bearbeiten** rechts neben der gewünschten [Eigenschaft der Safe Share-Organisationsverwaltung](/3.2/de/admin-platform/configuring-organisation-administration-properties#organisation-administration-properties).
4. Aktualisieren Sie im Dialogfeld **Konfigurationseigenschaft bearbeiten** das Feld **Eigenschaftswert** nach Bedarf.
5. Klicken Sie auf **Speichern**, und der Wert der Eigenschaft der Safe Share-Organisationsverwaltung wird mit sofortiger Wirkung geändert. <br />
   **Hinweise:**

   - Für Eigenschaften, deren Wert lediglich aus `Wahr` oder `Falsch` besteht, hat das Dialogfeld **Konfigurationseigenschaft bearbeiten** ein Kontrollkästchen **Eigenschaftswert**, das für `Wahr` aktiviert bzw. für `Falsch` deaktiviert sein sollte.
   - Die Namen der Eigenschaften der Safe Share-Organisationsverwaltung sind fest definiert und können nicht geändert werden.

## Eigenschaften der Safe Share-Organisationsverwaltung <a id="organisation-administration-properties" />

Die folgenden Eigenschaften der Safe Share-Organisationsverwaltung sind verfügbar:

| Eigenschaft | Detaillierte Beschreibung |
| --- | --- |
| Organisations-Administrator-E-Mail | <a id="org-admin-email" />Die Kontakt-E-Mail-Adresse, im Allgemeinen für einen [Organisations-Administrator](/3.2/de/admin-platform/administering-users-within-an-organisation#organisation-administrator-role), die:  <br />•  in E-Mail-Benachrichtigungen von Covata verwendet wird und <br />•  über den Link **Brauchen Sie Hilfe? ...** auf der Startseite für den **Authentifizierungscode** für die Zwei-Faktor-Authentifizierung (2FA) zugänglich ist, wenn sich ein Covata-Benutzer, für dessen [Account 2FA aktiviert ist](/3.2/de/admin-platform/administering-users-within-an-organisation#enabling-or-disabling-2fa-on-organisation-user-accounts), über die Covata-Anmeldeseite [anmeldet](/3.2/de/user/signing-in). <br />Wenn sich ein Covata-Benutzer nicht erfolgreich anmelden kann (meistens weil er für den zweiten Authentifizierungsfaktor keine Authentifizierungscodes mehr erzeugen kann), kann er diesen Link **Brauchen Sie Hilfe? ...** anklicken, um eine E-Mail an seinen Organisations-Administrator einzuleiten und eine Anforderung zur [Neukonfiguration von 2FA für den Benutzer-Account](/3.2/de/admin-platform/administering-users-within-an-organisation#re-configuring-2fa-for-an-organisation-user-account) zu senden. <br />  Weitere Informationen finden Sie unter [Verwaltung von Benutzern innerhalb einer Organisation](/3.2/de/admin-platform/administering-users-within-an-organisation) im Abschnitt [Safe Share-Organisationsverwaltung](/3.2/de/admin-platform/organisation-administration) dieser Anleitung . <br /> **Hinweise:**  <br />•  Der Standardwert für diese Eigenschaft ist leer. In diesen Fällen wird alternativ der Wert verwendet, der für die Eigenschaft [Admin-E-Mail](/3.2/de/admin-platform/configuring-platform-administration-properties#platform-admin-email) (anhand der [Eigenschaften der Systemdetails](/3.2/de/admin-platform/configuring-platform-administration-properties#system-details-properties) - siehe [Konfiguration von Eigenschaften der Safe Share-Verwaltung](/3.2/de/admin-platform/configuring-platform-administration-properties) ) definiert wurde. <br />•  Zwei-Faktor-Authentifizierung wird für einen Account vom Benutzer selbst über die [Safe Share-Webanwendung](/3.2/de/user/managing-your-account#enabling-or-disabling-2fa-for-your-account), über die [Organisationsverwaltung](/3.2/de/admin-platform/administering-users-within-an-organisation#enabling-or-disabling-2fa-on-organisation-user-accounts) oder die Safe Share-Verwaltung, von einem Safe Share-Administrator für [einen beliebigen Account eines Safe Share-Administrators](/3.2/de/admin-platform/administering-platform-administrator-users#enabling-or-disabling-2fa-for-a-platform-administrator) oder von einem Organisations-Administrator für [alle Mitglieder seiner Organisation](/3.2/de/admin-platform/configuring-organisation-administration-properties#enforce-2fa-for-organisation-members) aktiviert.  |
| Ist die Adressbuch-Funktion aktiviert? | <a id="address-book-feature" />Legt fest, ob die Adressbuch-Funktion der Organisation aktiviert ist (d. h. `Wahr`) oder nicht (d. h. `Falsch`). <br />  Die Adressbuch-Funktion ermöglicht es Benutzern, (anhand automatischer Vervollständigung) andere Covata-Benutzer-Mitglieder ihrer Organisation zu finden, indem sie bei der Freigabe eines Elements die ersten Zeichen der E-Mail-Adresse eines Mitglieder-Accounts eingeben. Wenn der Wert dieser Eigenschaft:  <br />•  `Wahr` lautet, wird diese Erkennungsfunktion auf alle Covata-Benutzer-Accounts angewendet, die Mitglieder der Organisation sind, sowie auf alle Kontakte des betreffenden Benutzers. <br />•  `Falsch` lautet, wird diese Erkennungsfunktion nur auf alle Kontakte des betreffenden Benutzers angewendet.  |
| Kurze Beschreibung der Organisation | Wie der Name dieser Eigenschaft andeutet, dient dieses Feld dazu, Organisations-Administratoren zusätzliche Informationen über ihre Organisation bereitzustellen. Beachten Sie, dass diese Beschreibung:  <br />•  auf den Oberflächen der Safe Share-Verwaltung und Organisationsverwaltung sowie in Safe Share-Anwendungen nirgendwo sonst angezeigt wird und <br />•  nicht gelöscht werden kann, wenn sie einmal definiert ist.  |
| E-Mail-Adresse der Kontaktperson der Organisation | <a id="organisations-contact-person" />Wie der Name dieser Eigenschaft besagt. Dieses Feld dient dazu, Safe Share-Administratoren die E-Mail-Adresse der Kontaktperson einer Organisation bereitzustellen. Diese Adresse erscheint auf der Seite [Organisationen](/3.2/de/admin-platform/administering-organisations) der [Safe Share-Verwaltung](/3.2/de/admin-platform#platform-administration) in der Spalte **Kontaktperson**. Beachten Sie, dass diese Kontaktperson:  <br />•  anfänglich die E-Mail-Adresse des Organisations-Administrators ist, der definiert wurde, als ein Safe Share-Administrator die Organisation der Covata-Plattform hinzugefügt hat, <br />•  auf den Oberflächen der Organisationsverwaltung sowie in Safe Share-Anwendungen nirgendwo sonst angezeigt wird und <br />•  nicht gelöscht werden kann. <br />**Hinweise:**  <br />•  Diese Eigenschaft ist hilfreich, wenn Safe Share-Administratoren Ihrer Instanz der Covata-Plattform in der Lage sein sollen, die für die Verwaltung Ihrer Organisation verantwortliche Person (per E-Mail) zu kontaktieren. <br />•  Diese Eigenschaft ist separat von der Eigenschaft [Organisations-Admin-E-Mail](/3.2/de/admin-platform/configuring-organisation-administration-properties#org-admin-email) (oben), deren Wert für Covata-Benutzer über E-Mail-Benachrichtigungen von Covata und den Link **Brauchen Sie Hilfe? ...** auf der Startseite für den **Authentifizierungscode** für die Zwei-Faktor-Authentifizierung (2FA) zugänglich ist. <br />•  Für weitere Informationen über das Hinzufügen von Organisationen zur Covata-Plattform siehe [Hinzufügen einer neuen Organisation](/3.2/de/admin-platform/administering-organisations#adding-a-new-organisation) in [Verwaltung von Organisationen](/3.2/de/admin-platform/administering-organisations).  |
| Sind Wasserzeichen für angezeigte Dateien aktiviert? | Legt fest, ob die Wasserzeichen-Funktion für alle innerhalb Ihrer Organisation erstellten anzeigbaren Dateien/sicheren Objekte aktiviert ist (d. h. `Wahr`) oder nicht (d. h. `Falsch`). <br />  Für die Wasserzeichen-Funktion gilt Folgendes:  <br />•  Sie ist nur auf Mitwirkende bei der Anzeige von ihnen freigegebenen Dateien anwendbar. Diese Funktion soll Mitwirkende davon abhalten, Ansichten von Dateien auf andere Weisen zu kopieren (z. B. durch Erfassung von Screenshots usw.). <br />•  Sie deckt die Ansicht einer Datei mit großem, halb transparentem Text ab, der die folgenden Informationen zeigt: die E-Mail-Adresse des aktuell angemeldeten, die Datei ansehenden Mitwirkenden, die URL der Covata-Plattform, die ID der Datei/des sicheren Objekts, gegebenenfalls die vom Dateibesitzer auf die Datei angewendete Klassifikation sowie das Datum/die Zeit der Anzeige der Datei.  |
| Standard-i18n-Einstellung für neue Benutzer und E-Mail-Benachrichtigungen | <a id="default-i18n-setting-for-organisation" />Die Standardsprache für alle Covata-Benutzer-Accounts, die auf der Covata-Plattform durch [Hinzufügen](/3.2/de/admin-platform/administering-users-within-an-organisation#adding-an-organisation-user-account) der Benutzer-Accounts zur Organisation neu erstellt werden <sup>&#42;</sup>.  <br />•  Diese Einstellung hat gegenüber der **Systemstandard**-Sprache, die von einem Safe Share-Administrator für seine Instanz der Covata-Plattform definiert wird, Vorrang. <br />•  Der anfängliche Wert dieser Eigenschaft ist die aktuelle Einstellung für die **Systemstandard**-Sprache. <br />**Hinweis:** Benutzer können die persönlichen Spracheinstellungen für ihre Accounts jederzeit anhand der Funktionen zur Bearbeitung ihrer eigenen Accounts in der [Safe Share-Webanwendung](/3.2/de/user/managing-your-account#updating-your-account-details) (oder [Organisationsverwaltung](/3.2/de/admin-platform/administering-users-within-an-organisation#editing-your-organisation-administrator-account)) ändern. <br /> <sup>&#42;</sup> Diese neuen Benutzer-Accounts werden erstellt, wenn die E-Mail-Adressen der betreffenden Benutzer auf der Covata-Plattform noch nicht registriert sind. |
| Für Mitglieder der Organisation Zwei-Faktor-Authentifizierung erzwingen | <a id="enforce-2fa-for-organisation-members" />Legt fest, ob die Funktion Zwei-Faktor-Authentifizierung (2FA) für alle Covata-Benutzer, die Mitglieder Ihrer Organisation sind, erzwungen wird (d. h. `Wahr`) oder nicht (d. h. `Falsch`). Dies schließt auch Ihren eigenen Organisations-Administrator-Account ein. <br /> **Hinweis:** Gehen Sie die Entscheidung, diesen Wert auf `Wahr` zu setzen, mit Vorsicht an. Wenn Mitglieder Ihrer Organisation (einschließlich Ihrer selbst) nicht auf die Konfiguration von 2FA für ihre Accounts vorbereitet sind, kann es sein, dass sie sich nicht mehr über die Covata-Anmeldeseite anmelden können und daher auf die folgenden Funktionen keinen Zugriff mehr haben:  <br />•  alle Organisationen auf der Covata-Plattform, bei denen die betreffenden Benutzer Mitglieder sind, und/oder <br />•  die Safe Share-Organisationsverwaltung für alle Organisationen, bei denen die betreffenden Benutzer die [Organisations-Administrator-Rolle](/3.2/de/admin-platform/administering-users-within-an-organisation#organisation-administrator-role) innehaben. <br />Für weitere Informationen über 2FA siehe [Aktivierung und Deaktivierung von 2FA für Benutzer-Accounts einer Organisation](/3.2/de/admin-platform/administering-users-within-an-organisation#enabling-or-disabling-2fa-on-organisation-user-accounts). |
| Element, das bei der Anmeldung eines neuen Benutzers in seiner Dateiliste erscheint | <a id="user-adoption-content" />Eine Datei/ein sicheres Objekt oder ein Ordner/eine Sammlung, die/das/der ein Organisations-Administrator für die automatische Freigabe an Covata-Benutzer innerhalb der Organisation auswählen kann, denen die [Ersteller-Rolle](/3.2/de/admin-platform/administering-users-within-an-organisation#originator-role) zugeteilt wird. <br />  Diese Funktion wird aktiv, wenn ein Organisations-Administrator eines seiner Elemente anhand dieser Eigenschaft auswählt. Das gewählte Element wird anschließend allen Benutzern innerhalb der Organisation, die nachfolgend die Ersteller-Rolle erhalten, freigegeben. Ein Benutzer-Account erhält die Ersteller-Rolle, wenn auf den Account Folgendes zutrifft:  <br />•  Der Account wird der Organisation [mit der Ersteller-Rolle hinzugefügt](/3.2/de/admin-platform/administering-users-within-an-organisation#adding-an-organisation-user-account) oder <br />•  der Account eines bestehenden Mitglieds der Organisation wird anschließend [bearbeitet](/3.2/de/admin-platform/administering-users-within-an-organisation#editing-an-organisation-user-account) und erhält die Ersteller-Rolle bzw. wird auf diese erweitert. <br />Der Zweck dieser Funktion ist es, Benutzern (die die Ersteller-Rolle erhalten) sofort Zugriff auf ein Element/Inhalt mit Informationen über die Nutzung von Safe Share-Produkten zur sicheren Freigabe von Daten zu geben. Für diese Eigenschaft kann jedoch ein beliebiges Element/ein beliebiger Inhalt ausgewählt werden. <br />  Beachten Sie, dass für diese Funktion die folgenden Anforderungen und Merkmale gelten:  <br />•  Ein Covata-Benutzer-Account mit der Organisations-Administrator-Rolle muss *auch* die Ersteller-Rolle innehaben, da das vom Organisations-Administrator gewählte Element in seinem Besitz sein muss. <br />•  Alle anhand dieser Funktion automatisch freigegebenen Elemente werden mit *Download*-Berechtigung freigegeben (unabhängig davon, ob das betreffende Element eine Datei oder ein Ordner ist). <br />•  Das dieser Eigenschaft aktuell zugewiesene Element kann unabhängig vom Besitz an diesem Element von jedem Organisations-Administrator geändert werden. Der betreffende Organisations-Administrator, der diese Eigenschaft ändert, kann jedoch nur ein Element in seinem Besitz wählen. <br />•  Sobald diese Funktion aktiv wird, wird bestehenden Covata-Benutzern mit Ersteller-Rolle innerhalb der Organisation das dieser Eigenschaft aktuell zugewiesene Element nicht mehr freigegeben. Wenn jedoch ein Account eines bestehenden Benutzers aus der Organisation [entfernt](/3.2/de/admin-platform/administering-users-within-an-organisation#removing-a-user-account-from-your-organisation) und anschließend wieder (mit der Ersteller-Rolle) hinzugefügt wird, wird das dieser Eigenschaft aktuell zugewiesene Element automatisch an den erneut hinzugefügten Benutzer-Account freigegeben. <br />•  Wenn sich das dieser Eigenschaft zugewiesene Element in einem Ordner befindet, erscheint es für Benutzer, denen innerhalb der Organisation nachfolgend die Ersteller-Rolle zugeteilt wird, auf der Stammebene im Bereich Elemente. <br />**Hinweise zu dieser Funktion (und Eigentümlichkeiten):**  <br />•  Gehen Sie die Entscheidung, dieses Element zu setzen, mit Vorsicht an. Sobald ein Element ausgewählt wurde, wird diese Funktion endgültig aktiviert und kann ab diesem Zeitpunkt nicht mehr deaktiviert werden. <br />•  Wenn ein Organisations-Administrator für diese Eigenschaft einen Ordner auswählt, wird nur der Ordner selbst (d. h. ohne seine vorhandenen Inhalte) automatisch an Benutzer freigegeben, die nachfolgend innerhalb der Organisation die Ersteller-Rolle erhalten. Wenn der betreffende Organisations-Administrator dem Ordner anschließend jedoch neue Elemente hinzufügt, werden diese neu hinzugefügten Elemente (automatisch aufgrund dieser Eigenschaft/Funktion) auch an alle Benutzer-Accounts freigegeben, denen der betreffende Ordner zuvor freigegeben war. Dieses Verhalten wird in einer künftigen Version der Covata-Plattform überarbeitet. <br />•  Wenn für diese Eigenschaft ein Ordner als Element ausgewählt ist und Sie den betreffenden Ordner (anhand eines Safe Share-Produkts oder einer anderen Client-Anwendung) entfernen möchten, ändern Sie diese Eigenschaft in ein anderes Element, *ehe* Sie den Ordner entfernen. Andernfalls wird der Ordner nicht vollständig aus Safe Share entfernt. Dieses Problem wird in einer künftigen Version der Covata-Plattform gelöst.  |
