## Supported methods and overview <a id="access-service-api-v1-userwhitelist-bulk-supported-methods-and-overview" />

- `POST` - used to [remove](/3.2/admin/managing-user-whitelists#removing-an-existing-user-whitelist-rule) one or more existing [user whitelist rules](/3.2/admin/managing-user-whitelists) (based on their user whitelist rule IDs), in a single action.

## Detailed description <a id="access-service-api-v1-userwhitelist-bulk-detailed-description" />

This API endpoint deletes one or more existing user whitelist rules from the Covata Platform.

Deleting one or more user whitelist rules (with at least one remaining) is likely to disable several Covata user accounts. Hence, before performing this action, it is advisable to first check which Covata user accounts will be disabled by calling the [&lt;access-service&gt;/api/v1/userwhitelist/check](/3.2/api/access-service-api-v1-userwhitelist-check) API endpoint with an **action** parameter value of **delete** in the JSON object, along with the **id**s (i.e. of each whitelist rule to be deleted) in the **items** array.

It is also possible to delete a single user whitelist rule by calling the `DELETE` method of the [&lt;access-service&gt;/api/v1/userwhitelist/\{userwhitelistId\}](/3.2/api/access-service-api-v1-userwhitelist-userwhitelistid) API endpoint.

Deleting the last user whitelist rule on the Covata Platform results in the user whitelist feature being disabled. When the user whitelist feature is disabled, be aware that:

- Covata user accounts *are not* [disabled](/3.2/api/access-service-api-v1-users-bulk) by *not having a user whitelist rule*.
- Directly [disabling or re-enabling Covata user accounts](/3.2/api/access-service-api-v1-users-userid-enable) has no impact on the user whitelist feature.
- Any LDAP user accounts that were disabled by not matching/complying with a user whitelist rule (when the user whitelist feature was enabled) are automatically re-enabled when the Covata Platform next synchronizes with the LDAP server.
