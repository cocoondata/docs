## URL structure <a id="access-service-api-v1-clientapps-url-structure" />

```text
https://access-service.xy-company.com/api/v1/clientapps
```

## Supported methods and overview <a id="access-service-api-v1-clientapps-supported-methods-and-overview" />

- `POST` - used to register a new [client application](/2.16/admin/configuring-client-applications) with the Covata Platform.
- `GET` - use to retrieve a list of field information for all client applications on the Covata Platform.

## Detailed description <a id="access-service-api-v1-clientapps-detailed-description" />

This API endpoint serves a number of purposes:

- Registers a new client application with the Covata Platform for the purposes of configuring that client application's identity (as well as the applcation's Covata user authentication and authorization) with the Covata Platform via OAuth 2.0.
- Retrieves a list of field information about the OAuth 2.0 configuration of all client applications currently registered on the Covata Platform.

## Supported roles <a id="access-service-api-clientapps-supported-roles" />

This API endpoint supports the following Covata user [roles](/2.16/admin/administering-users#a-users-roles) (as described in the [Covata Platform Administrator's Guide](/2.16/admin/index)):

- [System administrator](/2.16/admin/administering-users#system-administrator-role)

The Covata Platform's resources available to one of these Covata users (above) is determined by the access token passed in the [header](/2.16/api/access-service-api-v1-clientapps#access-service-api-v1-clientapps-required-headers) of requests to this endpoint.
