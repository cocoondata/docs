## URL structure <a id="access-service-api-v1-users-me-applications-approvals-approvalid-url-structure" />

```text
https://access-service.xy-company.com/api/v1/users/me/applications/approvals/{approvalId}
```

where `{approvalId}` is an application's approval ID.

## Supported methods and overview <a id="access-service-api-v1-users-me-applications-approvals-approvalid-supported-methods-and-overview" />

- `DELETE` - used to revoke the access that a third party (i.e. non-Covata) client application has to resources on the Covata Platform (which are available to the currently authenticated [Covata user](/2.16/admin/administering-users)<sup>&#42;</sup>), based on the application's approval ID.

<Note>

This method takes no parameters.

</Note>

## Detailed description <a id="access-service-api-v1-users-me-applications-approvals-approvalid-detailed-description" />

This API endpoint revokes the access that a third party (i.e. non-Covata) client application has to resources on the Covata Platform (which are available to the currently authenticated Covata user<sup>&#42;</sup>), based on this application's approval ID. This Covata user would have previously permitted the application access to their resources on the Covata Platform.

An application's approval ID is obtained by calling the [&lt;access-service&gt;/api/v1/users/me/applications/approvals](/2.16/api/access-service-api-v1-users-me-applications-approvals) API endpoint, which retrieves a list of information about all client applications that the currently authenticated Covata user has approved access to their resources on the Covata Platform.

Such a client application could be one that you or your organization is developing, where this application integrates with Covata technologies either using Covata's API or a Covata SDK.

<Note>

Before any client application can be granted access to a Covata user's resources, a Covata Platform administrator must first have [registered the client application](/2.16/api/access-service-api-v1-clientapps) on their Covata Platform.

</Note>

## Supported roles <a id="access-service-api-applications-approvals-approvalid-supported-roles" />

This API endpoint supports the following Covata user [roles](/2.16/admin/administering-users#a-users-roles) (as described in the [Covata Platform Administrator's Guide](/2.16/admin)):

- [Originator](/2.16/admin/administering-users#originator-role)
- [Collaborator](/2.16/admin/administering-users#collaborator-role)

The Covata Platform's resources available to one of these Covata users (above) is determined by the access token passed in the [header](/2.16/api/access-service-api-v1-users-me-applications-approvals-approvalid#access-service-api-v1-users-me-applications-approvals-approvalid-required-headers) of requests to this endpoint.

If the request succeeded, then an HTTP response status `200 OK` is returned.
