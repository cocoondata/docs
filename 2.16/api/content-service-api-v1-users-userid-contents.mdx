## URL structure <a id="content-service-api-v1-users-userid-contents-url-structure" />

```text
https://content-service.xy-company.com/api/v1/users/{userid}/contents
```

where `{userid}` is the ID of a Covata user.

## Supported methods and overview <a id="content-service-api-v1-users-userid-contents-supported-methods-and-overview" />

- `DELETE` - used to delete a [Covata user](/2.16/admin/administering-users)'s entire [Secure Object](/2.16/api/creating-secure-objects-and-collections#secure-object) content in storage (managed by the Covata Platform's Content Service).

<Note>

This method takes no parameters.

</Note>

## Detailed description <a id="content-service-api-v1-users-userid-contents-detailed-description" />

This API endpoint deletes a Covata user's entire Secure Object content in storage (managed by the Covata Platform's content service).

<Note>

If you intend to [delete a Covata user](/2.16/api/access-service-api-v1-users-userid) and change the state of all Secure Objects that were owned by this user to *Deleted*, then call this API endpoint on this Covata user *first*. This avoids problems where the available storage space reported by the Covata Platform may remain significantly lower and will continue to do so. See [&lt;access-service&gt;/api/v1/users/\{userid\}](/2.16/api/access-service-api-v1-users-userid) or [&lt;access-service&gt;/api/v1/users/bulk](/2.16/api/access-service-api-v1-users-bulk) for more information.

</Note>

## Supported roles <a id="content-service-api-users-userid-contents-supported-roles" />

This API endpoint supports the following Covata user [roles](/2.16/admin/administering-users#a-users-roles) (as described in the [Covata Platform Administrator's Guide](/2.16/admin/index)):

- [System administrator](/2.16/admin/administering-users#system-administrator-role)

The Covata Platform's resources available to one of these Covata users (above) is determined by the access token passed in the [header](/2.16/api/content-service-api-v1-users-userid-contents#content-service-api-v1-users-userid-contents-required-headers) of requests to this endpoint.

## Required headers <a id="content-service-api-v1-users-userid-contents-required-headers" />

The appropriate access token as the `Bearer` token:

- `Authorization: Bearer a1b2c3d4-e5f6-g7h8-i9j0-k1l2m3n4o5p6`

## Returns <a id="content-service-api-v1-users-userid-contents-returns" />

If the request succeeded, then an HTTP response status `200 OK` is returned.
