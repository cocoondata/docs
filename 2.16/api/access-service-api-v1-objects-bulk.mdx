## URL structure <a id="access-service-api-v1-objects-bulk-url-structure" />

```text
https://access-service.xy-company.com/api/v1/objects/bulk
```

## Supported methods and overview <a id="access-service-api-v1-objects-bulk-supported-methods-and-overview" />

- `POST` - used to [disable or (re-)enable](/2.16/admin/administering-files#disabling-or-re-enabling-secure-objects) one or more [Secure Objects](/2.16/api/creating-secure-objects-and-collections#secure-object).

## Detailed description <a id="access-service-api-v1-objects-bulk-detailed-description" />

This API endpoint disables or (re-)enables one or more Secure Objects.

It is also possible to disable or (re-)enable a single Secure Object by calling the [&lt;access-service&gt;/api/v1/objects/\{objectId\}/enable](/2.16/api/access-service-api-v1-objects-objectid-enable) API endpoint.

## Supported roles <a id="access-service-api-objects-bulk-supported-roles" />

This API endpoint supports the following Covata user [roles](/2.16/admin/administering-users#a-users-roles) (as described in the [Covata Platform Administrator's Guide](/2.16/admin)):

- [System administrator](/2.16/admin/administering-users#system-administrator-role)

The Covata Platform's resources available to one of these Covata users (above) is determined by the access token passed in the [header](/2.16/api/access-service-api-v1-objects-bulk#access-service-api-v1-objects-bulk-required-headers) of requests to this endpoint.

## Required headers <a id="access-service-api-v1-objects-bulk-required-headers" />

- `Authorization: Bearer a1b2c3d4-e5f6-g7h8-i9j0-k1l2m3n4o5p6` <br />
   where the `Bearer` token is the appropriate access token.
- `Content-Type: application/json`

## Required parameters <a id="access-service-api-v1-objects-bulk-required-parameters" />

The following required parameter must be sent in the URL of the POST request:

- **action** - enable or disable.

  **Example:**

  ```text
  https://access-service.xy-company.com/api/v1/objects/bulk?action=disable
  ```

## Optional parameters <a id="access-service-api-v1-objects-bulk-optional-parameters" />

The following optional parameter can be sent in the body of the POST request, as an individual member of a JSON object:

- **ids** - An array of one or more [Secure Object](/2.16/api/creating-secure-objects-and-collections#secure-object) IDs.

  **Example ():**

Although omitting the **ids** parameter above in a request serves no purpose, an empty JSON object must at least be passed in the body of POST requests to this endpoint for a successful response:

- `{}`

## Returns <a id="access-service-api-v1-objects-bulk-returns" />

If the request succeeded, then an HTTP response status `200 OK` is returned.
