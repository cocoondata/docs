## URL structure <a id="access-service-api-v1-users-userid-unlock-url-structure" />

```text
https://access-service.xy-company.com/api/v1/users/{userId}/unlock
```

where `{userId}` is the ID of a Covata user.

## Supported methods and overview <a id="access-service-api-v1-users-userid-unlock-supported-methods-and-overview" />

- `PUT` - used to [unlock](/3.0/admin/administering-users#unlocking-users-accounts) a [Covata user's](/3.0/admin/administering-users) account, based on the user's ID.

<Note>

This method takes no parameters.

</Note>

## Detailed description <a id="access-service-api-v1-users-userid-unlock-detailed-description" />

This API endpoint unlocks a Covata user's account, based on the Covata user's ID.

A Covata user's account can be come locked if the user of this account had entered their password incorrectly more than the Covata Platform's [configured maximum](/3.0/admin/configuring-administration-properties#maximum-number-of-password-retries) (which can be set through the [&lt;access-service&gt;/api/v1/config/server/\{configId\}](/3.0/api/access-service-api-v1-config-server-configid) API endpoint).

## Supported roles <a id="access-service-api-v1-users-userid-unlock-supported-roles" />

This API endpoint supports the following Covata user [roles](/3.0/admin/administering-users#a-users-roles) (as described in the [Covata Platform Administrator's Guide](/3.0/admin/index)):

- [System administrator](/3.0/admin/administering-users#system-administrator-role)

The Covata Platform's resources available to one of these Covata users (above) is determined by the access token passed in the [header](/3.0/api/access-service-api-v1-users-userid-unlock#access-service-api-v1-users-userid-unlock-required-headers) of requests to this endpoint.

## Required headers <a id="access-service-api-v1-users-userid-unlock-required-headers" />

The appropriate access token as the `Bearer` token:

- `Authorization: Bearer a1b2c3d4-e5f6-g7h8-i9j0-k1l2m3n4o5p6`

## Returns <a id="access-service-api-v1-users-userid-unlock-returns" />

If the request succeeded, then an HTTP response status `200 OK` is returned.
