## URL structure <a id="access-service-api-v1-groups-groupid-url-structure" />

```text
https://access-service.xy-company.com/api/v1/groups/{groupId}
```

where `{groupId}` is the ID of a group.

## Supported methods and overview <a id="access-service-api-v1-groups-groupid-supported-methods-and-overview" />

- `GET` - used to retrieve information about an existing [group](/3.1/admin/managing-groups), based on the group's ID.
- `PUT` - used to modify the fields of an existing group and/or the association of [labels](/3.1/admin/managing-labels) and the membership of [Covata users](/3.1/admin/administering-users) with this group.
- `DELETE` - used to delete an existing group.

<Note>

The `GET` and `DELETE` methods take no parameters.

</Note>

## Detailed description <a id="access-service-api-v1-groups-groupid-detailed-description" />

This API endpoint serves a number of purposes:

- Retrieves information about an existing group, using the group's ID. A group's ID can be obtained by calling the `GET` method of the [&lt;access-service&gt;/api/v1/groups](/3.1/api/access-service-api-v1-groups) API endpoint, which retrieves a list of field information for all existing groups on the Covata Platform. <br />
  **Tip:** All information (except the **description** member) returned in the [response](/3.1/api/access-service-api-v1-groups-groupid#access-service-api-v1-groups-groupid-returns-from-a-GET-or-PUT-request) from a `GET` method call to this API endpoint is also returned in the [response](/3.1/api/access-service-api-v1-groups#access-service-api-v1-groups-returns-from-a-GET-request) from a `GET` method call to the [&lt;access-service&gt;/api/v1/groups](/3.1/api/access-service-api-v1-groups) endpoint. Therefore, if you do not require a group's **description** when retrieving information about the group, there is no need to call the `GET` method on this API endpoint.
- Modifies the fields of an existing group and/or the association of labels and the membership of Covata users with this group, based on the group's ID. This endpoint's `PUT` method allows modification of a group's name and description, as well as:

  - the association (i.e. addition) of [labels](/3.1/api/access-service-api-v1-labels) with the group,
  - the removal of labels from the group and
  - the addition (i.e. membership) of Covata users to (or their removal from) this group.
- Deletes an existing group from the Covata Platform. <br />
  **Important:** Deleting an existing group removes any association between the Covata users who were members of this group as well as any labels that were associated with the group. Therefore, if a Covata user was shared a [Secure Object](/3.1/api/creating-secure-objects-and-collections#secure-object) with a label that is associated with one or more groups (of which the user is also a member) and the deletion of one of these groups results in the user:

  - Still remaining associated with this label (through the label's association with other groups to which the user is also a member), then the user will still have access to this Secure Object.
  - Losing their association with this label (because the user was not a member of any other group that had an association with this label), then the user loses access to this Secure Object.

## Supported roles <a id="access-service-api-groups-groupid-supported-roles" />

This API endpoint supports the following Covata user [roles](/3.1/admin/administering-users#a-users-roles) (as described in the [Covata Platform Administrator's Guide](/3.1/admin)):

- [System administrator](/3.1/admin/administering-users#system-administrator-role)

The Covata Platform's resources available to one of these Covata users (above) is determined by the access token passed in the [header](/3.1/api/access-service-api-v1-groups-groupid#access-service-api-v1-groups-groupid-required-headers) of requests to this endpoint.
