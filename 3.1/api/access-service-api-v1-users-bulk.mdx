## URL structure <a id="access-service-api-v1-users-bulk-url-structure" />

```text
https://access-service.xy-company.com/api/v1/users/bulk
```

## Supported methods and overview <a id="access-service-api-v1-users-bulk-supported-methods-and-overview" />

- `POST` - used to perform a specific action on one or more [Covata users](/3.1/admin/administering-users) (i.e. [disable, enable](/3.1/admin/administering-users#disabling-or-re-enabling-users), [expire tokens/sessions](/3.1/admin/administering-users#expiring-users-tokens-sessions), [force passwords to be reset](/3.1/admin/administering-users#forcing-users-to-reset-their-passwords) or [delete](/3.1/admin/administering-users#deleting-users)).

## Detailed description <a id="access-service-api-v1-users-bulk-detailed-description" />

This API endpoint performs any one of the following actions on one or more Covata users (each of which is specified by their Covata user ID):

- Disable or (re-)enable the account(s) of one or more Covata user(s). This can also be performed for an individual Covata user by calling the [&lt;access-service&gt;/api/v1/users/\{userId\}/enable](/3.1/api/access-service-api-v1-users-userid-enable) API endpoint.
- Expire (i.e. invalidate) all access/refresh tokens associated with the Covata user(s). This can also be performed for an individual:

  - Covata user by calling the [&lt;access-service&gt;/api/v1/users/\{userId\}/expire](/3.1/api/access-service-api-v1-users-userid-expire) API endpoint.
  - Access token (and its associated refresh token) by calling the [&lt;access-service&gt;/api/v1/auth/token/revoke](/3.1/api/access-service-api-v1-auth-token-revoke) API endpoint.
- Force the Covata user(s) password(s) to be reset. This can also be performed for an individual Covata user by calling the `PUT` method of the [&lt;access-service&gt;/api/v1/users/\{userid\}](/3.1/api/access-service-api-v1-users-userid) API endpoint.
- Delete the Covata user(s). This can also be performed for an individual Covata user by calling the `DELETE` method of the [&lt;access-service&gt;/api/v1/users/\{userid\}](/3.1/api/access-service-api-v1-users-userid) API endpoint. <br />
  **Important:** It is *strongly advised* that you first explicitly delete these users' entire Secure Object content in storage (that will require multiple calls to the [&lt;content-service&gt;/api/v1/users/\{userid\}/contents](/3.1/api/content-service-api-v1-users-userid-contents) API endpoint - one for each user being deleted) *before* calling this API endpoint (with the **action** parameter value of `delete`), which changes the state of all Secure Objects that these users currently own to *Deleted*. If you call this endpoint first, then the available storage space reported by the Covata Platform is likely to remain significantly lower and will continue to do so, since the Covata Platform can no longer authenticate these users to obtain the appropriate access tokens required to manipulate these Secure Objects' data in storage through the Covata API.

## Supported roles <a id="access-service-api-users-bulk-supported-roles" />

This API endpoint supports the following Covata user [roles](/3.1/admin/administering-users#a-users-roles) (as described in the [Covata Platform Administrator's Guide](/3.1/admin/index)):

- [System administrator](/3.1/admin/administering-users#system-administrator-role)

The Covata Platform's resources available to one of these Covata users (above) is determined by the access token passed in the [header](/3.1/api/access-service-api-v1-users-bulk#access-service-api-v1-users-bulk-required-headers) of requests to this endpoint.
