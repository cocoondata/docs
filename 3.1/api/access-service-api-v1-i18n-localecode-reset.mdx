## URL structure <a id="access-service-api-v1-i18n-localecode-reset-url-structure" />

```text
https://access-service.xy-company.com/api/v1/i18n/{localeCode}/reset
```

where `{localeCode}` is a supported locale code.

## Supported methods and overview <a id="access-service-api-v1-i18n-localecode-reset-supported-methods-and-overview" />

- `PUT` - used to reset a locale from a custom internationalization (i18n) bundle (which had been uploaded to the Covata Platform's Access Service) back to its built in version.

<Note>

This method takes no parameters.

</Note>

## Detailed description <a id="access-service-api-v1-i18n-localecode-reset-detailed-description" />

This API endpoint resets a locale from a custom i18n bundle (specified by `{localCode}`), which had been uploaded to the Covata Platform's Access Service) back to its built in version.

<Note>

- This endpoint can only be called on locales *with* existing i18n bundles that are built in to the Covata Platform.
- Any Covata users utilizing the locale of this custom i18n bundle (which they would have chosen through Safe Share) will automatically be reverted to use the existing i18n bundle of the same locale, when the bundle is reset.

</Note>

## Supported roles <a id="access-service-api-v1-i18n-localecode-reset-supported-roles" />

This API endpoint supports the following Covata user [roles](/3.1/admin/administering-users#a-users-roles) (as described in the [Covata Platform Administrator's Guide](/3.1/admin/index)):

- [System administrator](/3.1/admin/administering-users#system-administrator-role)

The Covata Platform's resources available to one of these Covata users (above) is determined by the access token passed in the [header](/3.1/api/access-service-api-v1-i18n-localecode-reset#access-service-api-v1-i18n-localecode-reset-required-headers) of requests to this endpoint.

## Required headers <a id="access-service-api-v1-i18n-localecode-reset-required-headers" />

The appropriate access token as the `Bearer` token:

- `Authorization: Bearer a1b2c3d4-e5f6-g7h8-i9j0-k1l2m3n4o5p6`

## Returns <a id="access-service-api-v1-i18n-localecode-reset-returns" />

If the request succeeded, then an HTTP response status `200 OK` is returned.
