---
title: "Configuring Safe Share Administration properties"
---

The **Configuration** page allows Safe Share administrators to [modify](/3.1/admin-platform/configuring-platform-administration-properties#modifying-a-platform-administration-property-value) a restricted set of properties on their Covata Platform instance, which are used to tweak specific functional aspects and the behavior of their Covata Platform instance.

<Note>

Other properties in configuration files can be modified by system administrators responsible for setting up on-site deployments of the Covata Platform.

</Note>

![Configuration/Properties page](/images/e430e5410be4-platform-administration-property-configuration-page.png)
<a id="platform-administration-properties" />The following Safe Share Administration properties are available:

| Property | Detailed description |
| --- | --- |
| Minimum password length | The minimum number of characters required for a [Local](/3.1/admin-platform/administering-users-within-an-organisation#account-type) user's password. This property has no affect on [LDAP](/3.1/admin-platform/administering-users-within-an-organisation#account-type) user's password since the authentication of LDAP users is delegated to their respective LDAP server. |
| Temporary password expiry time in hours | When a new [Local](/3.1/admin-platform/administering-users-within-an-organisation#account-type) Covata user account is created, the user receives an email notification containing a temporary password (generated by the Covata Platform), which the user requires to set their own password for their user account. Hence, the value of this property defines the validity of this temporary password. <br />**Note:** If this temporary password expires, the user can still set their password through the Covata Sign-in page by clicking either the **Don't have a password?** or **Forgot your password** button and following the instructions in the resulting email notification sent to their email address.  |
| Mobile users can set passcodes | This property's functionality has been superseded by the **Allow Device Registration** feature (available when [registering a client application on the Covata Platform](/3.1/admin-platform/configuring-client-applications#registering-a-new-client-application)). Therefore, this property is no longer used and will be removed in a future Covata Platform release. |
| Maximum number of password retries | <a id="maximum-number-of-password-retries" />The maximum number of incorrect sign-in attempts permitted by a Covata user mistyping their password before the user account becomes locked. The user will need to do one of the following to unlock their account:  <br />•  Follow the instructions in the email notification which is sent to the user after their account is locked. The email notification contains a link to unlock the user's account. The validity of this link is equivalent to the **Account lockout time in minutes** (below). <br />•  Wait until their account is unlocked; the duration of this period is defined by the **Account lockout time in minutes** (below). <br />•  Reset their password by clicking either **Don't have a password?** or **Forgot your password** on the Covata Sign-in page.  |
| Account lockout time in minutes | The amount of time that a Covata user needs to wait before their user account (which was locked as a result of the user mistyping their password beyond the **Maximum number of password retries** above, during sign-in) is automatically unlocked by the Covata Platform. This amount of time also defines the period for which the link to unlock a user's account (contained in the email notification sent to the user) is valid. <br />**Important:** Ensure this value is positive and do not set it to `0` (zero). Setting this value to `0` locks a user account indefinitely (as a result of the user mistyping their password beyond the **Maximum number of password retries** above) and as a Safe Share administrator, increases the risk of you locking yourself out of Safe Share Administration if you mistype your password. If this value was `0` following a Covata Platform upgrade, then change it to a positive value.  |
| Maximum number of email my password retries | <a id="maximum-number-of-email-my-password-retries" />The maximum number of times that a Covata user can click either **Don't have a password?** or **Forgot your password**, be sent an email notification containing either a one-time access link/password or password reset instructions *and* fail to successfully sign in, before their account is locked. <br /> **Notes:**  <br />•  Ensure that this value is positive and do not set it to `0` (zero). Doing so increases your risk (as a Safe Share administrator) of locking yourself out of Safe Share Administration in the event that you mistype your password. <br />•  Although a Covata user may click either **Don't have a password?** or **Forgot your password** successively, an email notification from this action is only sent out at a rate of once every five minutes. This default value is defined by a property that can be modified by system administrators responsible for setting up on-site deployments of the Covata Platform.  |
| Number of character type categories that must appear in a password | <a id="number-of-character-type-categories-that-must-appear-in-a-password" />There are four *categories* of *character types* that can be used in a password:  <br />•  Lower case letters <br />•  Uppercase letters <br />•  Numerals <br />•  Special characters <br />The value of this property determines how many of these four character type categories must be present in a password (whenever it is set) for this password to be valid. For instance:  <br />•  Specifying `1` means that the characters in a password only need to derive from one of the categories above. <br />•  Specifying `2` means that the characters in a password must derive from at least two of these categories, etc.  |
| The tracking code used for Google Analytics | The tracking code given to you when you sign up for Google Analytics. <br />**Note:** For Google Analytics to work with your Covata Platform instance, this value must be used in conjunction with **The tracking domain used for Google Analytics** (below).  |
| The tracking domain used for Google Analytics | The domain of your Covata Platform's web server. <br />**Note:** For Google Analytics to work with your Covata Platform instance, this value must be used in conjunction with **The tracking code used for Google Analytics** (above).  |
| Two-factor authentication configuration link expiry time in days | When two-factor authentication (2FA) has been enabled on a Covata user account (by the user themselves through the [Safe Share web application](/3.1/user/managing-your-account#enabling-or-disabling-2fa-for-your-account), [Organization Administration](/3.1/admin-platform/administering-users-within-an-organisation#enabling-or-disabling-2fa-on-organisation-user-accounts) or Safe Share Administration, by a Safe Share administrator on [any Safe Share administrator's account](/3.1/admin-platform/administering-platform-administrator-users#enabling-or-disabling-2fa-for-a-platform-administrator), or by an Organization administrator for [all members of their organization](/3.1/admin-platform/configuring-organisation-administration-properties#enforce-2fa-for-organisation-members)) the user receives an email notification informing them about this. This email notification contains a time-limited configuration link, which leads to step-by-step instructions for the user to:  <br />•  configure their mobile device with an appropriate authenticator application (aka authenticator app), as well as <br />•  configure the authenticator app with the Covata user account (thereby allowing the app to generate appropriate authentication codes). <br />Hence, the value of this property defines the validity of this configuration link. |
| Show smart banner on iOS devices linking to the native iOS client | Sets a 'flag' on the Covata Platform which results in a smart banner appearing at the top of [Safe Share web application](/3.1/user/index) pages whenever it is accessed through Safari on iOS devices. This encourages users of iOS devices who have clicked a direct URL to an item from '*A file/folder has been shared with you*' email notification (which opens the item in the Safe Share web application) to access the item in Safe Share for iOS instead (by clicking the link in the smart banner). |
| Maximum number of contacts allowed per user | The maximum number of contacts that any given Covata user can add to their account through the Safe Share [web application](/3.1/user/managing-your-account#managing-your-contacts), as well as Safe Share for [Windows](/3.1/windows/managing-your-account#managing-your-contacts) or iOS. |
| Maximum number of collaborators per file/folder | The maximum number of collaborators which are permitted on an item through the Safe Share [web application](/3.1/user/uploading-storing-and-sharing-content-securely#sharing-secure-content), as well as Safe Share for [Windows](/3.1/windows/uploading-storing-and-sharing-content-securely#sharing-secure-content) or iOS. <br />**Note:** Be aware that this limit includes collaborators on an item which have been *implicitly* inherited from folders (containing this item) to which collaborators have been *explicitly* added.  |
| Item shared notification frequency in minutes | The time interval defining the frequency with which email notifications for shared items (i.e. '*A file/folder has been shared with you*') are sent by the Covata Platform. <br />**Note:** If any given Covata user has multiple items shared with them during one of these time intervals, the user will receive a single email notification (at the end of the interval) listing all the items that were shared with them since the previous interval/notification they received.  |
| User adoption notification reminder frequency in days | The number of days between each of a series of user adoption email notifications being sent out to [new Covata users](/3.1/admin-platform/administering-users-within-an-organisation#adding-an-organisation-user-account) with the [Originator role](/3.1/admin-platform/administering-users-within-an-organisation#originator-role). See the **User adoption notification reminder enabled** property's description (below) for more information about these types of email notifications. <br />**Notes:** For this Safe Share Administration property to take effect, the **User adoption notification reminder enabled** property (below) must be set to `true`.  |
| User adoption notification reminder enabled | Determines whether (i.e. `true`) or not (i.e. `false`) the Covata Platform sends a series of user adoption email notifications to [new Covata users](/3.1/admin-platform/administering-users-within-an-organisation#adding-an-organisation-user-account) with the [Originator role](/3.1/admin-platform/administering-users-within-an-organisation#originator-role). Each of these email notifications contain tips and information to encourage these new Covata users to use Safe Share applications (for example, how to share data using these applications). <br /> **Notes:**  <br />•  There are a series of four user adoption email notifications which are sent out at a frequency defined by the **User adoption notification reminder frequency in days** property (above). The *user adoption email notification period* is defined as the number of different user adoption email notifications (four) multiplied by the **User adoption notification reminder frequency in days** property value (15 days by default), which is a default of 60 days. <br />•  User adoption email notifications are only sent out to new Covata user accounts *from the time their account is first created* (either through [Safe Share Administration](/3.1/admin-platform/administering-platform-administrator-users#adding-a-platform-administrator-account) or [Organization administration](/3.1/admin-platform/administering-users-within-an-organisation#adding-an-organisation-user-account)). If a Covata user with an existing account is added to a new/different organization (even with the [Originator role](/3.1/admin-platform/administering-users-within-an-organisation#originator-role)), they do not receive any user adoption email notifications. <br />•  If an existing Covata user is granted the Originator role for the first time (within any organization), they do not receive any user adoption email notifications unless their user account was granted the Originator role within the *user adoption email notification period* of their account's creation date. If so, such a user would receive user adoption email notifications for the trailing part of this period.  |

## Modifying a Safe Share Administration property value <a id="modifying-a-platform-administration-property-value" />

**To modify a Safe Share Administration property value:**

1. [Sign in](/3.1/admin-platform/accessing-platform-administration#signing-in-to-platform-administration) to Safe Share Administration.
2. Click the **Configuration** option on the left of the [Safe Share Administration interface](/3.1/admin-platform/accessing-platform-administration#the-platform-administration-interface) to open the **Configuration** page.
3. Click the **Edit** link to the right of the relevant [Safe Share Administration property](/3.1/admin-platform/configuring-platform-administration-properties#platform-administration-properties).
4. In the **Edit Configuration** dialog box, update the **Property value** field as required.
5. Click **Save** and the value of the Safe Share Administration property is modified with immediate effect. <br />
   **Notes:**

   - The **Modified** column's field value is updated to indicate the current date and time (i.e. when the property's value was last modified). If no date and time is indicated, then the property's value was never modified and its default value is being used.
   - For properties whose value consists of a simple `true` or `false`, the **Edit Configuration** dialog box has a **Property Value** check box, which should be selected for `true` or cleared for `false`.
   - It is not possible to modify the names of Safe Share Administration properties, since these are fixed.
