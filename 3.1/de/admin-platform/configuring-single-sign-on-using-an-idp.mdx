---
title: "Konfiguration der Einzelanmeldung über einen IdP"
---

Ein Safe Share-Administrator kann einen externen IdP-Service (Identitätsanbieter) konfigurieren, der über die SAML (Security Assertion Markup Language) 2.0 mit der betreffenden Covata-Plattform-Instanz interagiert. (Beachten Sie, dass die Covata-Plattform SAML Version 1.0 nicht unterstützt.)

Sobald diese Konfiguration erfolgreich aufgebaut wurde, kann die Covata-Plattform die Authentifizierung *jeglicher* Covata-Benutzer über eine separate URL an diesen IdP-Service delegieren und so über die Covata-Plattform Unterstützung für Einzelanmeldung (single sign-on) anbieten. („*Jegliche* Covata-Benutzer“ beinhalten [Safe Share-Administratoren](/3.1/de/admin-platform/administering-platform-administrator-users) sowie [Benutzer innerhalb einer Organisation](/3.1/de/admin-platform/administering-users-within-an-organisation), unabhängig von der/den Organisation(en), der/denen sie angehören.)

Wenn sich ein Benutzer gegenüber dem IdP-Service der Covata-Plattform erfolgreich authentifiziert hat, gibt der IdP der Covata-Plattform automatisch einen SAML-Token zurück (der den betreffenden Benutzer repräsentiert), und diese tauscht den SAML-Token gegen einen Zugriffs-/Aktualisierungs-Token.

Für die Konfiguration eines IdP-Service auf der Covata-Plattform wird Folgendes *benötigt*:

- eine **IdP-Metadaten-Datei** - dies ist eine XML-Datei gemäß dem [SAML-Standard](http://saml.xml.org/saml-specifications), die Sie von Ihrem IdP-Service erhalten; sie enthält Konfigurationsdaten, die Drittanbieterdiensten (wie der Covata-Plattform) die Interaktion mit dem IdP-Service selbst ermöglichen.
- das **E-Mail-Feld des IdP** - Covata-Benutzer-Accounts (auf der Covata-Plattform) werden mit diesem Benutzerfeld des IdP-Service abgeglichen. Beachten Sie bitte, dass die Konfigurationsinformationen für dieses Feld eventuell nicht Bestandteil der IdP-Metadaten-Datei bilden.
- ein **privater Schlüssel** und ein **öffentliches X.509-Zertifikat** (für die **Covata-Plattform**) - dieses X.509-Zertifikat wird (manuell oder automatisch) an den IdP-Service hochgeladen, der es dann für die sichere Kommunikation mit der Covata-Plattform nutzt. <br />
  **Hinweis:** Die IdP-Metadaten-Datei enthält auch ein öffentliches X.509-Zertifikat für den IdP-Service, das die Covata-Plattform für die sichere Kommunikation mit dem IdP-Service nutzt.

<Warning>

Der Zugriffsdienst der Covata-Plattform unterstützt *keine* Erstellung von Benutzern auf einem IdP-Service. Benutzer auf einem IdP-Service müssen derzeit direkt über den IdP selbst hinzugefügt oder aktualisiert werden (z. B. über einen LDAP-Server). Für auf der Covata-Plattform neu erstellte Covata-Benutzer-Accounts, die:

- manuell über die [Organisationsverwaltung](/3.1/de/admin-platform/administering-users-within-an-organisation#adding-an-organisation-user-account) oder die [Safe Share-Verwaltung](/3.1/de/admin-platform/administering-platform-administrator-users#adding-a-platform-administrator-account) hinzugefügt wurden (und die den [Account-Typ](/3.1/de/admin-platform/administering-users-within-an-organisation#account-type) **Lokal** haben) oder
- automatisch von der Covata-Plattform als Benutzer mit [Ad-hoc-Rolle](/3.1/de/admin-platform/administering-users-within-an-organisation#adhoc-role) (und dem Account-Typ **Extern**) hinzugefügt wurden,

gilt jedoch, dass sie dem IdP-Service *nicht automatisch hinzugefügt werden*.

Ist daher ein konfigurierter IdP-Service auf der Covata-Plattform aktiviert, können sich die betreffenden Benutzer nur über die eigene Anmelde-URL der Covata-Plattform authentifizieren (und nicht über die URL der Covata-Plattform für die Einzelanmeldung, die die Authentifizierung an den IdP-Service delegiert).

Haben jedoch die betreffenden Covata-Benutzer anschließend einen äquivalenten, direkt beim IdP-Service angelegten Account (d. h. mit derselben E-Mail-Adresse), können sie die URL der Covata-Plattform für die Einzelanmeldung nutzen.

</Warning>

## Hinzufügen einer IdP-Service-Konfiguration <a id="adding-an-idp-service-configuration" />

**Hinzufügen einer IdP-Servicekonfiguration zur Covata-Plattform:**

1. [Melden Sie sich](/3.1/de/admin-platform/accessing-platform-administration#signing-in-to-platform-administration) bei der Safe Share-Verwaltung an.
2. Klicken Sie auf die Option **SAML** links auf der [Oberfläche Safe Share-Verwaltung](/3.1/de/admin-platform/accessing-platform-administration#the-platform-administration-interface), um die Seite **SAML** aufzurufen.
3. Klicken Sie auf die Schaltfläche **IdP-Konfiguration hinzufügen**.
4. Füllen Sie im Dialogfeld **IdP-Konfiguration hinzufügen** die in der [Tabelle](/3.1/de/admin-platform/configuring-single-sign-on-using-an-idp#idp-service-configuration-fields) (unten) beschriebenen Felder für die Konfiguration des IdP-Service aus.
5. Klicken Sie auf **Speichern**, und die IdP-Service-Konfiguration erscheint auf der Seite **SAML**. <br />
   **Hinweise:**

   - Sobald der IdP-Service erfolgreich konfiguriert wurde, können sich Benutzer dem IdP-Service gegenüber authentifizieren, indem sie im URL-Feld ihres Browsers die Basis-URL Ihrer Instanz der Safe Share-Webanwendung angeben (die auch die URL der Covata-Plattform ist), gefolgt von `/sso` (für Einzelanmeldung), also z. B.: <br />
     `https://safe-share.xy-firma.de/sso`
   - Wenn Covata-Benutzer in der Lage sein sollen, sich vom IdP-Service abzumelden, vergewissern Sie sich, dass der Service entsprechend konfiguriert ist und dass den betreffenden Benutzern gegebenenfalls ausreichende Informationen zur Verfügung gestellt werden, wie sie sich vom IdP abmelden. Andernfalls bleiben die Benutzer bei der Safe Share-Webanwendung angemeldet, wenn sie die URL für die Einzelanmeldung (siehe oben) erneut besuchen und dann auf die Schaltfläche **Einzelanmeldung** klicken.
   - Es kann nur eine IdP-Service-Konfiguration hinzugefügt werden, die dann wie im Folgenden beschrieben bearbeitet werden kann.

<a id="idp-service-configuration-fields" />Die folgende Tabelle beschreibt alle für IdP relevanten Felder, die die Covata-Plattform benötigt, um eine erfolgreiche Verbindung zu einem LDAP-Server/-Benutzerverzeichnis herzustellen.

| Feld | Beschreibung |
| --- | --- |
| Zeitunterschiedspuffer | Der maximal zulässige Zeitunterschied (in Sekunden) zwischen den Uhren des IdP-Service (Identitätsanbieter) und dem Zugriffsdienst der Covata-Plattform. <br />  Es wird davon ausgegangen, dass zwischen den Server-Uhren des IdP-Service und des Zugriffsdienstes ein inhärenter Zeitunterschied besteht. Für die Definition der **Gültigkeit der SAML-Sitzung** unten (zu der der Wert dieses **Zeitunterschiedspuffers** addiert wird) muss daher der zwischen dem IdP-Service und dem Zugriffsdienst maximal zulässige Zeitunterschied festgelegt werden. |
| Gültigkeit der SAML-Sitzung | Die SAML-Sitzung (d. h. vom IdP-Service ausgegebene Asssertions) bleibt diese Anzahl Sekunden lang gültig. <br />  Nach der erfolgreichen Authentifizierung eines Benutzers beim IdP-Service erstellt der IdP-Service eine *Assertion*, die im Allgemeinen im Zwischenspeicher abgelegt und anschließend allen entsprechenden, mit Einzelanmeldung arbeitenden Serviceanbietern (zu denen auch der Zugriffsdienst der Covata-Plattform zählt) zur Verfügung gestellt wird. Diese Assertion enthält im Allgemeinen Folgendes:  <br />•  den ([oben](/3.1/de/admin-platform/configuring-single-sign-on-using-an-idp) beschriebenen) SAML-Token selbst, der für den authentifizierten Benutzer steht <br />•  eine *Erstellungszeit*, die angibt, wann der IdP-Service die Assertion erstellt hat. <br />Auf Anforderung des Zugriffsdienstes sendet der IdP-Service seine (im Zwischenspeicher abgelegte) Assertion (mit dem SAML-Token) dem Zugriffsdienst, wenn der Zugriffs-Token (und Aktualisierungs-Token) des Covata-Benutzers abläuft - für weitere Informationen über die Gültigkeitsdauer von Zugriffs-/Aktualisierungs-Token siehe die [Tabelle](/3.1/de/admin-platform/configuring-client-applications#client-application-fields) zur [Konfiguration von Client-Anwendungen](/3.1/de/admin-platform/configuring-client-applications). Dieser SAML-Token überschreibt daher effektiv die Gültigkeitsdauer von Zugriffs-/Aktualisierungs-Token (da ein gültiger SAML-Token vom Zugriffsdienst gegen einen neuen Zugriffs-/Aktualisierungs-Token ausgetauscht wird). <br />  Die *gesamte Gültigkeit der SAML-Sitzung* wird als die Summe aus dem Wert für die **Gültigkeit der SAML-Sitzung** und dem Wert für den **Zeitunterschiedspuffer** oben berechnet. Ist der Zeitunterschied zwischen der aktuellen Zeit des Zugriffsdienstes und der *Erstellungszeit* der Assertion im Zwischenspeicher größer als diese *gesamte Gültigkeit der SAML-Sitzung*, lehnt die Covata-Plattform die betreffende Assertion des IdP-Service (und ihren SAML-Token) ab. Der Benutzer muss sich in diesem Fall gegenüber dem IdP-Service erneut authentifizieren (und der Service muss eine neue Assertion mit einer neuen Erstellungszeit anlegen). <br /> **Hinweise:**  <br />•  Definieren Sie eine optimale **Gültigkeit der SAML-Sitzung**, die für die anderen Serviceanbieter, die den konfigurierten IdP-Service nutzen, geeignet ist:  <br />•  Wird dieser Wert zu hoch angesetzt, kann dies das Risiko erhöhen, dass die Sitzung eines Benutzers auf der Covata-Plattform kompromittiert wird. <br />•  Wird dieser Wert zu gering angesetzt, können Benutzer zu häufig gezwungen werden, sich beim IdP-Service erneut zu authentifizieren, was die Nutzung dieses IdP-Service durch andere Serviceanbieter beeinträchtigen kann. <br />•  Beachten Sie, dass alle Benutzer-Sitzungen mit gültigen Zugriffs-/Aktualisierungs-Token offen bleiben, wenn die Covata-Plattform eine Assertion eines IdP-Service (aufgrund einer Überschreitung der *gesamten Gültigkeit der SAML-Sitzung*) abgelehnt hat, sofern sich Benutzer nicht abmelden oder ihre Token/Sitzungen beendet werden (über die [Safe Share-Webanwendung](/3.1/de/user/managing-your-account#terminating-your-accounts-sessions), die [Organisationsverwaltung](/3.1/de/admin-platform/administering-users-within-an-organisation#terminating-your-organisation-administrator-accounts-sessions) oder die [Safe Share-Verwaltung](/3.1/de/admin-platform/administering-platform-administrator-users#terminating-your-platform-administrator-accounts-sessions)).  |
| Feld IdP-E-Mail | Der Name des IdP-Metadatenfelds, das den E-Mail-Adressen der Benutzer entspricht <br />**Hinweis:** Definiert eine IdP-Metadaten-Datei ihr E-Mail-Feld in dieser Datei, überschreibt der in diesem **Feld IdP-E-Mail** angegebene Wert den Wert in der IdP-Metadaten-Datei.  |
| IdP-Metadaten-Datei | Gibt an, ob die IdP-Metadaten-Datei auf die Covata-Plattform hochgeladen und dort konfiguriert wurde. Diese Datei bildet eine der ([oben](/3.1/de/admin-platform/configuring-single-sign-on-using-an-idp) beschriebenen) Anforderungen für die Konfiguration eines IdP-Service auf der Covata-Plattform. <br />**Hochladen the IdP-Metadaten-Datei:** <br />•  [Melden Sie sich](/3.1/de/admin-platform/accessing-platform-administration#signing-in-to-platform-administration) bei der Safe Share-Verwaltung an. <br />•  Klicken Sie auf die Option **SAML** links auf der [Oberfläche Safe Share-Verwaltung](/3.1/de/admin-platform/accessing-platform-administration#the-platform-administration-interface), um die Seite **SAML** aufzurufen. <br />•  Klicken Sie auf die Schaltfläche  **IdP-Metadaten hochladen**. <br />•  Klicken Sie im Dialogfeld **IdP-Metadaten** auf **XML-Datei mit IdP-Metadaten hochladen**. <br />•  Navigieren Sie zu Ihrer IdP-Metadaten-Datei (XML-Datei gemäß dem SAML-Standard) mit den Konfigurationsinformationen, anhand deren die Covata-Plattform mit dem IdP-Service interagieren kann, und wählen Sie diese Datei aus. <br />•  Klicken Sie auf **Schließen**, um das Dialogfeld **IdP-Metadaten** zu schließen. <br /> **Hinweis:** Sie können eine hochgeladene IdP-Metadaten-Datei jederzeit entfernen, indem Sie dieses Dialogfeld **IdP-Metadaten** öffnen, die Schaltfläche **IdP-Konfiguration entfernen** anklicken (die die Schaltfläche **IdP-Metadaten-XML-Datei hochladen** ersetzt, sobald eine IdP-Metadaten-Datei erfolgreich auf die Covata-Plattform hochgeladen wurde) und anschließend **Speichern** anklicken, um die Entfernung zu übernehmen. <br />Sobald eine IdP-Metadaten-Datei auf die Covata-Plattform hochgeladen wurde, müssen auch ein privater Schlüssel und ein Zertifikat des Dienstanbieters (SP) auf die Covata-Plattform hochgeladen werden - dies ist eine weitere der ([oben](/3.1/de/admin-platform/configuring-single-sign-on-using-an-idp) beschriebenen) Anforderungen für die Konfiguration eines IdP-Service auf der Covata-Plattform. <br />**Hochladen des privaten Schlüssels und Zertifikats des Dienstanbieters:** <br />•  Vergewissern Sie sich, dass Sie bei der Safe Share-Verwaltung [angemeldet sind](/3.1/de/admin-platform/accessing-platform-administration#signing-in-to-platform-administration) und die Option **SAML** links auf der [Oberfläche Safe Share-Verwaltung](/3.1/de/admin-platform/accessing-platform-administration#the-platform-administration-interface) angeklickt haben, um die Seite **SAML** aufzurufen. <br />•  Klicken Sie auf die Schaltfläche **SP-Zertifikat hochladen**. <br />•  Befolgen Sie im Dialogfeld **Privater Schlüssel und Zertifikat des Dienstanbieters** die Anweisungen oben, um einen privaten Schlüssel und ein Zertifikat zu erstellen, anhand deren die Covata-Plattform dem IdP-Service die sichere Kommunikation mit der Covata-Plattform gestattet. <br />•  Klicken Sie auf **Speichern**, um den privaten Schlüssel und das Zertifikat zu speichern. <br />•  Klicken Sie auf **Schließen**, um das Dialogfeld **Privater Schlüssel und Zertifikat des Dienstanbieters** zu schließen. <br /> **Hinweise:**  <br />•  Sie können einen konfigurierten privaten Schlüssel und ein Zertifikat eines Dienstanbieters jederzeit entfernen. Öffnen Sie hierzu das Dialogfeld **Privater Schlüssel und Zertifikat des Dienstanbieters** und klicken Sie auf die Schaltfläche **Zertifikat entfernen** (die **Speichern** ersetzt, sobald ein privater Schlüssel und ein Zertifikat eines Dienstanbieters auf der Covata-Plattform konfiguriert sind). <br />•  Sobald ein privater Schlüssel und ein Zertifikat eines Dienstanbieters konfiguriert sind, können Sie eine XML-Datei des Zertifikats gemäß dem SAML-Standard herunterladen (um sie manuell auf den IdP-Service hochzuladen). Klicken Sie hierzu auf den Link **Metadaten herunterladen** im Dialogfeld **Privater Schlüssel und Zertifikat des Dienstanbieters** oder direkt auf der Seite **SAML** in der Safe Share-Verwaltung.  |
| IdP aktiviert? | Gibt an, ob die Covata-Plattform (bei der delegierten Authentifizierung und Einzelanmeldung) mit ihrem konfigurierten IdP-Service arbeiten kann. <br />**Hinweis:** Dieses Feld bleibt leer, bis der Covata-Plattform die IdP-Service-Konfiguration hinzugefügt wurde.  |

## Bearbeitung der IdP-Service-Konfiguration <a id="editing-the-idp-service-configuration" />

1. [Melden Sie sich](/3.1/de/admin-platform/accessing-platform-administration#signing-in-to-platform-administration) bei der Safe Share-Verwaltung an.
2. Klicken Sie auf die Option **SAML** links auf der [Oberfläche Safe Share-Verwaltung](/3.1/de/admin-platform/accessing-platform-administration#the-platform-administration-interface), um die Seite **SAML** aufzurufen.
3. Klicken Sie auf den Link **IdP-Konfiguration bearbeiten**.
4. Ändern Sie im Dialogfeld **IdP-Konfiguration bearbeiten** die in der [Tabelle](/3.1/de/admin-platform/configuring-single-sign-on-using-an-idp#idp-service-configuration-fields) (siehe oben) beschriebenen Felder für die Konfiguration des IdP-Service.
5. Klicken Sie auf **Speichern**, und die IdP-Service-Konfiguration wird aktualisiert.

## Deaktivierung und Reaktivierung der IdP-Service-Konfiguration <a id="disabling-or-re-enabling-the-idp-service-configuration" />

Die Deaktivierung der IdP-Service-Konfiguration deaktiviert die Möglichkeit zur Einzelanmeldung bei der Covata-Plattform (über diesen konfigurierten IdP-Service).

Ist die IdP-Service-Konfiguration deaktiviert, können Benutzer daher die Basis-URL Ihrer Instanz der Safe Share-Webanwendung, gefolgt von `/sso` zur Anmeldung bei Covata nicht mehr verwenden, z. B.:

`https://safe-share.xy-firma.de/sso`

**Deaktivierung, Aktivierung und Reaktivierung der IdP-Service-Konfiguration:**

1. [Melden Sie sich](/3.1/de/admin-platform/accessing-platform-administration#signing-in-to-platform-administration) bei der Safe Share-Verwaltung an.
2. Klicken Sie auf die Option **SAML** links auf der [Oberfläche Safe Share-Verwaltung](/3.1/de/admin-platform/accessing-platform-administration#the-platform-administration-interface), um die Seite **SAML** aufzurufen.
3. Gehen Sie anschließend wie folgt vor:

   - *Deaktivierung der IdP-Service-Konfiguration* - klicken Sie auf die (grüne) Schaltfläche **Aktiviert**, um sie auf **Deaktiviert** umzuschalten.
   - *Aktivierung oder Reaktivierung der IdP-Service-Konfiguration* - klicken Sie auf die (rote) Schaltfläche **Deaktiviert**, um sie auf **Aktiviert** umzuschalten.
