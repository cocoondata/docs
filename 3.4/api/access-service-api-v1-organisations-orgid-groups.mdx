## URL structure <a id="access-service-api-v1-organisations-orgid-groups-url-structure" />

```text
https://access-service.xy-company.com/api/v1/organisations/{orgId}/groups
```

where `{orgId}` is the ID of an organization.

## Supported methods and overview <a id="access-service-api-v1-organisations-orgid-groups-supported-methods-and-overview" />

- `POST` - adds a new [group](/3.4/admin-org/managing-groups) to an organization (specified by `orgId`).
- `GET` - retrieves a list of information for all groups defined within an organization (specified by `orgId`).

## Detailed description <a id="access-service-api-v1-organisations-orgid-groups-detailed-description" />

This API endpoint serves a number of purposes:

- Adds a new group to an organization (specified by `orgId`). <br />
  **Notes:**

  - Associating this new group with one or more [classifications](/3.4/admin-org/managing-classifications) would allow these classifications to restrict file sharing to any Covata users who are members of this group.
  - For more information about adding one or more [Covata users](/3.4/api/authentication-and-authorisation) [in an organization](/3.4/admin-org/administering-users-within-an-organisation) to a group, see [&lt;access-service&gt;/api/v1/organisations/\{orgId\}/groups/\{groupId\}](/3.4/api/access-service-api-v1-organisations-orgid-groups-groupid). Also see [&lt;access-service&gt;/api/v1/organisations/\{orgId\}/labels](/3.4/api/access-service-api-v1-organisations-orgid-labels) for more information about adding new classifications to an organization.
- Retrieves a list of information for all groups defined within an organization (specified by `orgId`).

## Supported roles and conditions <a id="access-service-api-v1-organisations-orgid-groups-supported-roles-and-conditions" />

This API endpoint supports requests utilizing Covata user accounts with the following [roles](/3.4/admin-org/administering-users-within-an-organisation#an-organisation-users-roles) (as described in the [Organization Administrator's Guide](/3.4/admin-org/index)) and conditions:

- [Organization administrator](/3.4/admin-org/administering-users-within-an-organisation#organisation-administrator-role) - when this user is a member of the organization specified by `{orgId}` in the request's URL.

The Covata Platform's resources available to one of these Covata users (above) is determined by the access token submitted in the [header](/3.4/api/access-service-api-v1-organisations-orgid-groups#access-service-api-v1-organisations-orgid-groups-required-headers) of requests to this endpoint.

## Required POST-request parameters <a id="access-service-api-v1-organisations-orgid-groups-required-post-request-parameters" />

The following required parameters must be sent in the **body** of the POST request, each as individual members of a **JSON object**:

- **name** - The name of the new group to be added to the organization specified by `{orgId}` in the request's URL. <br />
  **Example (request):**

  ```json
  {
    "name": "Staff with security clearance"
  }
  ```

## Optional POST-request parameters <a id="access-service-api-v1-organisations-orgid-groups-optional-post-request-parameters" />

The following optional parameters can also be sent in the **body** of the POST request, each as individual members of the **JSON object** that includes the [Required POST-request parameters](/3.4/api/access-service-api-v1-organisations-orgid-groups#access-service-api-v1-organisations-orgid-groups-required-post-request-parameters) above:

- **description** - The description of the new group to be added to the organization specified by `{orgId}` in the URL. <br />
  **Example (request):**

  ```json
  {
    "name": "Staff with security clearance",
    "description": "XY Company staff members who have security clearance."
  }
  ```

## Optional GET-request parameters <a id="access-service-api-v1-organisations-orgid-groups-optional-get-request-parameters" />

The following optional parameters can be sent in the **URL** of the GET request:

- **limit** - An integer value from `0` to `100`, representing the maximum number of items to be returned in the response, where an individual item is information about a group defined in the organization (specified by `{orgId}` in the request's URL). If this parameter is omitted, then its value is `0` by default, which does not apply restrictions to the number of items returned in the response.
- **offset** - A value representing the count order of all retrievable items (i.e. groups in the organization specified by `{orgId}` in the URL) returned in the response. Calls to this API endpoint may amount to potentially large numbers of items being returned from the Covata Platform. Since the order of these items in the response could differ significantly, based on the values of the **orderBy** and **sortBy** parameters below, this **offset** parameter provides pagination for items returned in responses, allowing items to be retrieved from any count greater than `0` (i.e. the first item returned in a response). If this parameter is omitted, then its value is `0` by default.
- **orderBy** - An enumeration (enum) value representing the order in which items (i.e. groups in the organization specified by `{orgId}` in the URL) are returned in the response. This parameter orders items according to the value of the **sortBy** parameter specified below. Ordering items can be in either ascending alphanumeric order (by specifying the value `ASC` for this parameter) or descending order (by specifying the value `DESC`). If this parameter is omitted, then its value is `ASC` by default.
- **sortBy** - A value representing the field (i.e. member) of a retrieved item by which items (i.e. groups in the organization specified by `{orgId}` in the URL) returned in the response will be sorted. Valid field values for this parameter include:

  - `name` - the name of the group and
  - `description` - the description of the group.

  **Example (request):**

  ```text
  https://access-service.xy-company.com/api/v1/organisations/760756644367081472/groups?sortBy=name
  ```

## Returns <a id="access-service-api-v1-organisations-orgid-groups-returns" />

If the request succeeded, then an HTTP response status `200 OK` is returned.

For successful requests only, a JSON-formatted response containing the following members is also returned:

- **items** ( *from GET requests only* ) - An array containing information about all existing groups defined in the organization (specified by `{orgId}` in the request's URL), where these groups have been filtered by any [parameters](/3.4/api/access-service-api-v1-organisations-orgid-groups#access-service-api-v1-organisations-orgid-groups-optional-get-request-parameters) submitted in the request. Each element of this array contains information about one of these groups (represented as an object containing the following members unless otherwise stated).
- **id** - The ID of the (new) group.
- **labelCount** ( *from GET requests only* ) - The number of classifications which are currently associated with the group.
- **memberCount** ( *from GET requests only* ) - The number of Covata user accounts which are currently members of the group.
- **description** - The description of the (new) group.
- **name** - The name of the (new) group.
- **count** ( *from GET requests only* ) - The total number of items (i.e. groups defined in the organization specified by `{orgId}` in the request's URL) that can be returned in the response.
- **offset** ( *from GET requests only* ) - The value of the **offset** which had been used in the request to this API endpoint. <br />
  **Example (response from a POST request - adding a new group to an organization):**

  ```json
  {
      "description": {
          "value": "XY Company staff members who have security clearance."
      },
      "name": {
          "value": "Staff with security clearance"
      },
      "id": "767238352499154944"
  }
  ```
